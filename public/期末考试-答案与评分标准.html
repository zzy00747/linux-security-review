一、选择题（共 10 题，24 分）

第 1 题（3 分）基础

题干：在 32 位 x86 架构中，下列寄存器与其典型用途的对应关系，正确的是：

正确答案：D．EIP 存放当前将要执行指令的地址，每执行一条指令后自动递增

解析：EIP 是指令指针寄存器，保存下一条将要执行指令的地址，每条指令执行后自动递增（PPT 第1讲明确：EIP is incremented after each instruction，并被 CALL、RET、JMP 及条件跳转修改）。认为 ESP 存返回地址的学生混淆了「栈指针」与「栈中内容」——返回地址是被 call 压入栈中的数据，ESP 本身只指向栈顶；认为 EBP 存栈顶的学生把 EBP（栈基址，用于稳定访问参数和局部变量）与 ESP 搞反了；认为 EAX 存段基址的学生混淆了通用寄存器与段寄存器（CS/DS/ES/SS 才存段选择子）。

易错：ESP 指栈顶、EBP 指栈基；EIP 是指令地址不是栈地址。三者别混。

第 2 题（3 分）基础

题干：AT&T 格式汇编指令 movl %esp, %ebp 中的后缀 l 表示：

正确答案：B．操作数宽度为 32 位（long word），即一次处理 4 个字节

解析：AT&T 汇编用后缀表示操作数宽度：b 表示 8 位、w 表示 16 位、l 表示 32 位、q 表示 64 位（PPT 第1讲：b、w、l、q 分别代表 8 位、16 位、32 位、64 位）。把 l 理解为 load 的学生把操作数宽度后缀误当成了指令助记符的一部分；把 l 理解为 local 的学生完全虚构了含义；把 l 理解为 8 位的学搞混了 l 与 b。

易错：b=8位、w=16位、l=32位、q=64位。l 是 long word 不是 load。

第 3 题（2 分）中档

题干：把 hello.c 编译为可执行文件需经过预处理、编译、汇编、链接四个阶段，下列命令与产物的对应关系，正确的是：

正确答案：C．gcc -c hello.s -o hello.o，产物是 ELF 格式的可重定位目标文件

解析：gcc -c 把汇编源文件汇编成机器指令，产物 .o 已经是 ELF 格式的可重定位目标文件（PPT 第6讲：汇编后形成的 .o 格式的文件已经是 ELF 格式文件了）。认为 -E 产物是 .s 的学生把预处理与编译搞混了——-E 的产物是 .i 预处理文件，.s 是 -S 的产物；认为 -S 产物是 .o 的学生把编译与汇编搞混了；认为链接产物是共享目标文件的学生混淆了可执行文件与动态链接库（.so）。

易错：-E→.i、-S→.s、-c→.o、链接→可执行文件。四步命令与产物必须一一对应。

第 4 题（2 分）中档

题干：关于 fork() 系统调用的返回值，下列叙述正确的是：

正确答案：B．父进程中返回子进程的 PID，子进程中返回 0，创建失败返回 -1

解析：fork() 调用一次返回两次：在父进程中返回新创建子进程的 PID（大于 0），在子进程中返回 0，出错时返回 -1（PPT 第6讲简化 Shell 程序正是用 pid < 0 判错、pid == 0 走子进程分支、pid > 0 走父进程分支）。认为父进程返回 0 的学生把父子分支的判断条件完全颠倒，会导致父子进程行为互换；认为两者都返回子 PID 的学生忽略了子进程无法靠返回值区分自己与父进程；认为父进程返回 1 的学生把返回值当成了布尔标志。

易错：父得子PID（>0）、子得0、错得-1。判断分支千万别写反。

第 5 题（2 分）中档

题干：iptables 四表中，用于实现源地址与目的地址转换（NAT）的是：

正确答案：A．nat 表，可作用于 PREROUTING、INPUT、OUTPUT、POSTROUTING 四条链

解析：nat 表负责地址转换，可作用于 PREROUTING、INPUT、OUTPUT、POSTROUTING 四条链（PPT 第7讲原文）。认为 filter 表做地址转换的学生混淆了「过滤」与「转换」——filter 才是过滤功能，作用于 INPUT、FORWARD、OUTPUT 三条链；mangle 表虽可作用于五条链，但它的职责是修改数据包内容（如 TTL、TOS）；raw 表用于在连接跟踪之前处理报文，不是做 NAT。

易错：filter 管过滤（3 链）、nat 管地址转换（4 链）、mangle 管改包内容（5 链）、raw 管连接跟踪前（2 链）。

第 6 题（3 分）基础

题干：/etc/passwd 文件中一行内容为 root:x:0:0:root:/root:/bin/bash，其中第三个字段 0 表示：

正确答案：D．用户的 UID，其中 0 专指超级用户 root

解析：/etc/passwd 每行七个字段依次为：用户名、密码占位符、UID、GID、描述信息、主目录、登录 Shell。第三个字段是 UID，0 是超级用户 root 的专属 UID。认为第三个字段是 inode 号的学生把文件系统概念错误地套用到用户数据库上；认为第三个字段是 GID 的学生数错了字段位置（GID 是第四个字段）；认为它表示密码占位符序号的学生混淆了第二字段（x）与第三字段。

易错：passwd 七字段顺序：用户名:密码占位:UID:GID:描述:主目录:Shell。第三个是 UID。

第 7 题（2 分）拉分

题干：关于 Linux 文件的 inode 与文件名，下列说法正确的是：

正确答案：A．inode 记录文件的权限、属主、大小和 block 位置，但不记录文件名

解析：inode 记录文件的全部属性（权限、属主、时间戳、大小、block 号码等），唯独不记录文件名——文件名保存在目录项中，目录项负责把「名字」映射到「inode 号」（PPT 第9讲明确这一分工）。认为文件名存在 inode 中的学生把目录项的职责错给了 inode，所以误以为改名会改 inode（实际改名只改目录项）；认为硬链接会复制 inode 的学生正好说反了——硬链接就是多个目录项指向同一个 inode，链接数加一；认为删除时 inode 立即回收且数据清零的学生忽略了 extundelete 能恢复文件这一事实（PPT 第9讲：删除只是标记，数据仍留在 block 中）。

易错：inode 不存文件名，文件名在目录项；硬链接共享同一 inode；删除后数据仍可被 extundelete 恢复。

第 8 题（2 分）中档

题干：下列关于安全扫描工具用途与特点的描述，正确的是：

正确答案：B．masscan 采用异步无状态扫描机制，适合大网段高速端口扫描

解析：masscan 采用异步无状态扫描，先发出大量探测包再统一收包，速度远高于 nmap，适合大网段快速端口扫描（PPT 第10讲）。认为 nmap 不能做主机发现的学生忽略了 nmap 的 -sn 等主机发现选项；认为 nikto 是主机发现工具的学生混淆了用途——nikto 是 Web 服务器扫描器，检查 Web 配置与已知漏洞；认为 OpenVAS 只能扫 Web 漏洞的学生低估了它——OpenVAS 是完整的漏洞扫描系统，覆盖系统与服务层漏洞。

易错：nmap 两者都能做；masscan 快在大网段；nikto 专扫 Web；OpenVAS 是综合漏洞扫描。

第 9 题（3 分）基础

题干：按部署位置划分，入侵检测系统可分为 NIDS 与 HIDS，下列对应关系正确的是：

正确答案：A．NIDS 部署在网络关键节点分析流量，HIDS 部署在单台主机上监控主机行为

解析：NIDS（网络型入侵检测系统）部署在网络关键节点，通过抓包分析网段流量发现攻击特征；HIDS（主机型入侵检测系统）安装在单台主机上，监控文件完整性、日志、进程与系统调用（PPT 第11讲）。认为 NIDS 装在单机上的学生把两者的 N（Network）与 H（Host）含义搞反；认为 HIDS 装在网络节点上的学生同样颠倒了部署位置；认为区别在于是否具备阻断能力的学生混淆了 IDS 与 IPS——IDS 只检测告警，IPS 才具备阻断能力，这是另一组对比。

易错：NIDS=网络节点看流量，HIDS=单机看主机行为；有没有阻断能力是 IDS 与 IPS 的区别。

第 10 题（2 分）拉分

题干：C 程序运行后，进程内存布局中各区域与其存放内容的对应关系，正确的是：

正确答案：C．栈存放函数的局部变量和返回地址，由系统自动分配与释放，向低地址方向增长

解析：栈用于存放函数调用过程中的局部变量、参数和返回地址，由系统自动分配释放，且栈向低地址方向增长（PPT 第1讲：Stack grows down）。认为堆存放全局变量的学生混淆了堆与数据段——全局变量和静态变量在 .data/.bss，堆是 malloc 动态分配的；认为 .bss 存放已初始化变量的学生把 .bss 与 .data 搞反，且 .bss 恰恰不占文件空间；认为 .text 存放未初始化全局变量的学生把代码段与数据段搞反，.text 存的是机器指令。

易错：栈=局部变量+返回地址（向下长）；堆=malloc 动态分配；.data=已初始化全局；.bss=未初始化全局（不占文件）；.text=机器指令。

二、填空题（共 10 题，25 分）

第 11 题（3 分）基础

题干：在 32 位 x86 中，专门用于指向当前栈顶的寄存器是 ____（填写寄存器缩写，全大写）。

参考答案：ESP / esp / %esp

解析：ESP（Extended Stack Pointer）始终指向当前栈顶。push 操作先把 ESP 减 4 再写入数据，pop 操作先读出数据再把 ESP 加 4。与之配合的 EBP 指向栈基址，用于在函数内部稳定地访问参数和局部变量。

易错：ESP 指栈顶（动态变化），EBP 指栈基（函数内固定），两者别混。

第 12 题（3 分）基础

题干：x86 中 CS、DS、ES、SS 这一组寄存器统称为 ____ 寄存器（填两个汉字）。

参考答案：段 / 段寄存器 / 段址

解析：CS（Code Segment）代码段寄存器、DS（Data Segment）数据段寄存器、ES（Extra Segment）附加段寄存器、SS（Stack Segment）堆栈段寄存器，合称段寄存器，存放各段的段选择子（段基址的高位部分），与偏移量组合形成线性地址。

易错：段寄存器存的是段选择子，不是线性地址本身。

第 13 题（2 分）中档

题干：内嵌汇编语句 asm volatile("movq %%rax,%0" : "=m"(val3) : "g"(val1)) 中，约束符 "=m" 表示该操作数是一个输出操作数，且存放在 ____ 中（填「内存」或「寄存器」）。

参考答案：内存 / 存储器 / memory

解析：内嵌汇编的约束符中，m 表示内存操作数（memory），r 表示通用寄存器，g 表示由编译器自由选择寄存器或内存，= 表示该操作数是只写的输出，+ 表示既读又写。所以 "=m"(val3) 的含义是：val3 作为输出，编译器直接把内存地址交给汇编代码去写，不经过寄存器中转。

易错：m=内存、r=寄存器、g=任意、=只写、+读写。

第 14 题（2 分）中档

题干：要查看一个 ELF 文件的节头表（Section Header Table）信息，应使用 readelf 的 ____ 选项（写选项，如 -h）。

参考答案：-S / -S / —S

解析：readelf -S 显示节头信息。对照记忆：-h 显示 ELF 文件头、-l 显示程序头表（段表）、-s 显示符号表、-r 显示重定位信息、-a 等价于全选。注意 -S 为大写，与 -s（符号表）含义完全不同。

易错：-S 看节头、-s 看符号表、-l 看段表，大小写与字母都要分清。

第 15 题（2 分）中档

题干：C 程序中未初始化的全局变量存放在 ____ 节，该节在可执行文件中不占实际空间，程序运行时由系统用 0 初始化（填写节名，带点号）。

参考答案：.bss / bss / .BSS

解析：.bss（Block Started by Symbol）存放未初始化的全局变量和静态变量，属于静态内存分配。因为运行时初值恒为 0，没必要在文件里存一堆零字节，只记录需要多大空间即可，其 section type 为 SHT_NOBITS，所以在 readelf -S 的输出里看不到它的实际数据。

易错：.bss 不占文件空间但占内存空间；.data 才是已初始化变量。

第 16 题（3 分）基础

题干：要禁止源地址为 192.168.100.20 的数据包进入本机，应执行的命令是：iptables -A INPUT -s 192.168.100.20 -j ____（填写动作名）。

参考答案：DROP / drop / REJECT / reject

解析：iptables -A INPUT -s 192.168.100.20 -j DROP 表示在 INPUT 链末尾追加一条规则，匹配源地址 192.168.100.20 的数据包并直接丢弃。也可用 REJECT，区别在于 REJECT 会向源端返回一个不可达的响应报文，而 DROP 静默丢弃、源端只能等到超时。从安全角度 DROP 更好，因为 REJECT 的响应报文会向攻击者泄漏「这里有主机」的信息。

易错：DROP 静默丢弃、REJECT 返回响应；安全场景优先 DROP 以免暴露主机存在。

第 17 题（2 分）拉分

题干：若 INPUT 链中已存在一条禁止 192.168.20.0/24 网段的 DROP 规则，现在要单独放行该网段内的 192.168.20.115，必须把新规则插入到该 DROP 规则之前，应使用 ____ 选项（填写选项，如 -A）。

参考答案：-I / -I / -i

解析：iptables 规则按顺序逐条匹配，一旦命中就执行动作并停止后续匹配。若用 -A 追加，放行规则会排在 DROP 之后，永远轮不到执行，192.168.20.115 依然被丢弃。必须用 -I INPUT 把规则插入到链首（或 -I INPUT 2 插到指定位置），使其先于 DROP 规则被匹配。这是 iptables 配置最典型的顺序陷阱。

易错：规则顺序决定结果：放行规则必须排在 DROP 之前，否则永远不生效。用 -I 不用 -A。

第 18 题（4 分）基础

题干：/etc/passwd 文件中每一行由 ____ 个字段组成，字段之间用冒号分隔（填写阿拉伯数字）。

参考答案：7 / 七

解析：/etc/passwd 每行七个字段，依次是：用户名、密码占位符（通常为 x，真实密码在 /etc/shadow）、UID、GID、用户描述信息、用户主目录、登录 Shell。例如 root:x:0:0:root:/root:/bin/bash 中，各字段分别为 root / x / 0 / 0 / root / /root / /bin/bash。

易错：passwd 是 7 字段，shadow 是 9 字段，别记混。

第 19 题（2 分）中档

题干：/etc/shadow 文件中密码字段若以 $6$ 开头，表示该密码使用 ____ 算法进行加密（填写算法名称或编号说明）。

参考答案：SHA-512 / sha512 / SHA512 / sha-512

解析：/etc/shadow 密码字段的 $id$ 部分标识哈希算法：$1$ 表示 MD5、$5$ 表示 SHA-256、$6$ 表示 SHA-512。$6$ 之后到下一个 $ 之间是盐值（salt），再往后是密码哈希值。SHA-512 输出 512 位摘要，抗暴力破解能力远强于 MD5。

易错：$1$=MD5、$5$=SHA-256、$6$=SHA-512，编号越大越安全。

第 20 题（2 分）中档

题干：使用 nmap 对 192.168.1.0/24 网段只做主机发现、不做端口扫描，应使用的选项是 ____（写选项，如 -sV）。

参考答案：-sn / -sn / -sP

解析：nmap -sn 192.168.1.0/24 表示只进行主机发现（ping 扫描），通过 ICMP echo、TCP SYN 到 443、TCP ACK 到 80、ARP 等多种探测手段判断主机是否在线，不进行端口扫描。旧版本中该选项写作 -sP。若要同时识别服务版本则用 -sV，全端口扫描用 -p-。

易错：-sn 只探活、-sV 探服务版本、-sS 是 SYN 半开扫描，三者用途不同。

三、简答题（共 5 题，24 分）

第 21 题（5 分）中档

题干：简述 Linux 系统调用的三层结构（xyz / system_call / sys_xyz），并说明库函数 API 与系统调用之间的关系。

参考答案与评分要点见下方解析

解析：参考答案：
① API 层（xyz）：用户程序调用的库函数，如 glibc 提供的 time()、fork()、open() 等。它们是系统调用的封装，负责把参数按约定放入寄存器、执行陷入指令、取回返回值。
② 系统调用入口层（system_call）：由陷入指令（int 0x80 / sysenter / syscall）进入内核后执行的统一入口，负责保存现场（保存用户态寄存器）、根据系统调用号在系统调用表中查找对应的服务例程、传递参数，处理完成后恢复现场并返回用户态。
③ 服务例程层（sys_xyz）：具体实现某功能的内核函数，如 sys_time、sys_fork、__x64_sys_execve。它完成实际的内核工作。
关系：库函数 API 是系统调用的「外壳」，一个 API 可能对应一个系统调用（如 fork），也可能完全不涉及系统调用（如纯计算的 strlen），还可能是多个系统调用的组合。用户程序并不直接调用 sys_xyz，只能通过 API 触发陷入，由内核代为执行。
评分要点：三层各 1 分，API 与系统调用的关系（封装、非一一对应）1 分。

易错：不要把「库函数」与「系统调用」等同。strlen 是库函数但不是系统调用；一个 API 可能封装多个系统调用。

第 22 题（5 分）中档

题干：简述函数调用时堆栈框架的建立与拆除过程，并说明 EBP 与 ESP 在其中的作用。

参考答案与评分要点见下方解析

解析：参考答案：
建立（进入被调函数时）：
① pushl %ebp：把调用者的 EBP 压栈保存（ESP 减 4）。
② movl %esp, %ebp：把当前 ESP 赋给 EBP，EBP 从此固定指向本函数栈框架的基址，之后 ESP 无论怎么变，都能靠 EBP 加固定偏移访问参数和局部变量。
③ subl $N, %esp：抬高栈顶，为局部变量预留 N 字节空间。
拆除（返回前）：
④ movl %ebp, %esp：把 ESP 恢复到 EBP 位置，一次性丢弃所有局部变量空间。
⑤ popl %ebp：弹出并恢复调用者的 EBP。
⑥ ret：弹出返回地址并跳转回调用点。
作用：EBP 是「锚点」，提供稳定的参数/局部变量寻址基准（参数在 EBP+8 起、局部变量在 EBP-4 起）；ESP 是「游标」，始终指向栈顶，随 push/pop 动态变化。二者配合使函数调用可以任意嵌套。
评分要点：建立三步 2 分，拆除三步 1 分，EBP/ESP 分工 1 分。

易错：顺序不能乱：先 push ebp 再 mov esp,ebp；拆除时先 mov ebp,esp 再 pop ebp。漏掉 movl %ebp,%esp 会导致栈失衡。

参考答案与评分要点见下方解析

解析：参考答案：
① 触发陷入：用户态执行 int 0x80 / sysenter / syscall 指令，CPU 根据中断描述符表（IDT）或 MSR 寄存器跳转到内核预设的系统调用入口。

⑤ 执行内核服务：sys_xyz 在内核态完成实际工作，期间可能访问用户态地址空间（需用 copy_from_user / copy_to_user 校验）。

评分要点：答出四点即可满分（每点 1 分），其中「切换内核栈」和「保存/恢复现场」是必须提到的关键点。

易错：容易漏掉「切换到内核栈」这一步。用户态和内核态用的是两个不同的栈，这是态切换的核心动作之一。

第 26 题（7 分）中档

题干：在 Linux 中执行 ls -l /usr/local/bin/tool，显示结果如下：

-rwsr-xr-- 1 alice dev 1024 Nov 19 10:00 /usr/local/bin/tool
（1）写出该文件的数字权限表示（用四位八进制数，如 0644）。（4 分）
（2）说明权限串中 s 位的名称、含义，以及它可能带来的安全风险。（4 分）

参考答案与评分要点见下方解析

解析：（1）数字权限表示：4755
逐段拆解：
· 特殊位段：该文件属主位出现 s 而非 x，说明 SUID 位被置 1，特殊位值 = 4。
· 属主段 rws：r=4、w=2、s 占据 x 位置且 SUID=1，故该段为 4+2+1=7。
· 组段 r-x：r=4、-=0、x=1，故为 4+0+1=5。
· 其他段 r--：r=4、-=0、-=0，故为 4。
合并：特殊位 4 + 属主 7 + 组 5 + 其他 4 = 4755。
（若特殊位无设置则写作 0755，本题因有 s 位故为 4755。）

（2）s 位的名称、含义与风险
· 名称：SUID（Set User ID，设置用户 ID 位）。出现在属主执行位时为小写 s（表示 SUID 置位且执行位也置位），若为大写 S 则表示 SUID 置位但执行位未置位。
· 含义：普通用户执行该文件时，进程的有效用户 ID（EUID）会临时变为文件属主（此例为 alice）的 UID，而不是执行者自己的 UID。程序运行结束后 EUID 恢复。
· 安全风险：若文件属主是 root（如 /usr/bin/passwd），则任何用户执行它都能获得 root 权限运行其中的代码。一旦该程序存在缓冲区溢出、命令注入等漏洞，攻击者就能借它提权到 root。因此生产环境应定期用 find / -perm -4000 -type f 审计所有 SUID 文件，删除不必要的 SUID 位（chmod u-s）。
评分要点：（1）特殊位 4 得 2 分、三段各 0.5 分、最终 4755 得 1 分；（2）SUID 名称 1 分、EUID 变为属主 2 分、风险说明 1 分。

易错：常见错误：把 rws 算成 7 却忘了额外加特殊位 4，写成 0755。s 位在 x 位置时该段仍算 1 分（因为执行位有效）。

第一次（汇编执行前）：val1:1,val2:2,val3:0
第二次（汇编执行后）：val1:1+val2:2=val3:3

题干：如下所示为某段汇编代码，请在右侧写出其对应的 C 语言代码（变量名自行命名，函数名保持 g、f、main）：

g:
    pushl %ebp
    movl  %esp, %ebp
    movl  8(%ebp), %eax
    addl  $3, %eax
    popl  %ebp
    ret

f:
    pushl %ebp
    movl  %esp, %ebp
    subl  $4, %esp
    movl  8(%ebp), %eax
    movl  %eax, (%esp)
    call  g
    movl  %ebp, %esp
    popl  %ebp
    ret

main:
    pushl %ebp
    movl  %esp, %ebp
    subl  $4, %esp
    movl  $8, (%esp)

    addl  $1, %eax
    movl  %ebp, %esp
    popl  %ebp

参考答案与评分要点见下方解析

解析：参考答案：

int g(int x) {
    return x + 3;
}

int f(int x) {
    return g(x);
}

int main(void) {
    return f(8) + 1;
}
逐函数推导：
· g：movl 8(%ebp), %eax 取第一个参数（EBP+8 是参数位置，因为 EBP+4 是返回地址），addl $3, %eax 加 3，ret 返回 eax。故 int g(int x) { return x + 3; }。
· f：subl $4, %esp 预留 4 字节局部空间（存放传给 g 的实参），movl 8(%ebp), %eax 取自己的参数，movl %eax, (%esp) 把它放到栈顶作为 g 的实参，call g 调用，返回值在 eax 中直接作为 f 的返回值。故 int f(int x) { return g(x); }。
· main：movl $8, (%esp) 把立即数 8 压到栈顶作为 f 的实参，call f 后 eax 得 f(8) 的返回值，addl $1, %eax 再加 1。故 return f(8) + 1;。
关键识别点：EBP+8 取第一个参数、EAX 传返回值、(%%esp) 传实参、call 后紧跟 addl 说明返回值被继续运算。
评分要点：g 正确 1.5 分、f 正确 1.5 分、main 正确 2 分（含 f(8)+1 的运算顺序）。

易错：常见错误：把 EBP+8 写成 EBP+4（忘记返回地址占 4 字节）；漏掉 main 里的 addl $1 而写成 return f(8)；把 f 里的 subl $4 误认为是局部变量而多写一个变量声明。

movl   %esp, %ebp
pushl  %ebp
pushl  $8
addl   $4, %esp
popl   %ebp

（2）标明当前栈顶和栈基的地址位置。（2 分）

参考答案与评分要点见下方解析

解析：逐条推演：
· 初始：ESP = 0x1000，EBP 未定。
· pushl $8：ESP 先减 4 得 0x0FFC，再把 8 写入 [0x0FFC]。
· movl %esp, %ebp：EBP = ESP = 0x0FFC。
· pushl %ebp：ESP 减 4 得 0x0FF8，把 EBP 的值 0x0FFC 写入 [0x0FF8]。
· pushl $8：ESP 减 4 得 0x0FF4，把 8 写入 [0x0FF4]。
· addl $4, %esp：ESP 加 4 得 0x0FF8（栈顶回退一格，[0x0FF4] 的数据仍在内存中但已不属于栈的有效范围）。
· popl %ebp：先读出 [0x0FF8] 的值 0x0FFC 送入 EBP，再让 ESP 加 4 得 0x0FFC。

地址        内容          说明
0x0FF4      8             已被 addl $4 弹出栈顶范围，数据仍残留
0x0FF8      0x0FFC        已被 popl 弹出，数据仍残留
0x0FFC      8             ← 当前栈顶（ESP 指向）
有效栈范围是 [0x0FFC, 0x1000)。

（2）栈顶与栈基位置
· 栈顶（ESP）= 0x0FFC，指向内容 8。
· 栈基（EBP）= 0x0FFC（因最后一条 popl %ebp 把 0x0FFC 恢复进了 EBP）。
即最终 ESP 与 EBP 恰好都等于 0x0FFC，二者重合。
评分要点：（1）三个单元地址与内容各 1 分（共 3 分），需正确体现 push 减 4、add 加 4 的效果；（2）ESP 值 1 分、EBP 值 1 分，须明确写出 0x0FFC。

易错：三个易错点：① push 是「先减后写」，pop 是「先读后加」，顺序写反会算错地址；② addl $4,%esp 只是抬高栈顶，不清除内存，所以 [0x0FF4] 的 8 仍然存在；③ 最后 popl %ebp 恢复的是最初 push 进去的 0x0FFC，不是 8。

· 进程 C：第三次分支（(pid=fork())==0）的子进程，命中后打印时间字符串 ctime(&timep) 的返回值（形如 Wed Nov 19 13:20:00 2026），随后 return。
· 进程 D：第四个分支（brother）的子进程，命中后打印 brother process，随后 return。
· 进程 E：第五个分支的条件是 (pid=fork()) < 0，而 fork 成功时只会返回子 PID（>0）或 0，永不小于 0（除非创建失败），因此 「我的学号是 9527」这条在正常情况下不会打印——这是本题设置的干扰项。
· 进程 G、H：第六个分支（(pid=fork())==0）的子进程。由于 B 与 E 都会走到这个分支并各自 fork 一次，因此该分支会产生 两个子进程，各打印一次 我的姓名是 nicai。
结论：终端打印共 5 条，分别是：
① father process:pid=<A的pid> —— 1 次
② Wed Nov 19 13:20:00 2026（ctime 格式的时间字符串）—— 1 次
③ brother process —— 1 次
④ 我的姓名是 nicai —— 2 次
（实际输出顺序不确定，取决于各进程被调度执行的先后。）

（3）父子进程关系图

            A (main)
            │ fork#1
     ┌──────┴──────┐
     A(父)          B(子,pid=0)
  打印 father        │ fork#2
                 ┌───┴────┐
                 B(父)     C(子)
                  │       打印 ctime
              fork#3
             ┌────┴────┐
           B(父)      D(子)
                    打印 brother
              fork#4
             ┌────┴─────┐
           B(父)       E(子)
          fork#5         │ fork#6
        ┌───┴───┐    ┌───┴───┐
      B(父)   G(子)  E(父)  H(子)
            打印 nicai    打印 nicai
说明：A 打印 father 后立即结束；B 一路作为父进程向下 fork 三次（fork#2/#3/#4/#5 中作为父）；C 打印时间、D 打印 brother、G 与 H 各打印一次 nicai；E 作为 fork#5 的子进程继续执行 fork#6 再产生 H。第五分支（学号）因条件恒不成立而不产生打印。
评分要点：（1）命令正确 2 分（有 gcc、源文件、-o 输出三要素）；（2）每类打印 0.5 分，其中「nicai 出现 2 次」和「学号不打印」是关键判别点（共 2 分）；（3）关系图结构正确 1 分、标注各子进程打印内容 1 分。

易错：三个高频错误：① 以为 fork 后只有子进程继续执行，漏掉父进程也继续走 else-if 链，导致进程数算少；② 把第五分支的 (pid=fork())<0 误认为会执行，多写一条「我的学号是 9527」；③ 忘记 else-if 链「命中即跳出」的特性，以为一个进程会打印多条。

第 31 题（4 分）拉分

题干：小明大学毕业后进入某互联网公司担任网络管理员，负责维护管理公司基于 Linux 的 Web 服务器。为了提高服务器的安全防护水平，小明在服务器上配置了防火墙。请根据该场景回答如下问题：
（1）小明在终端输入了什么命令可以显示 INPUT 链下 policy 为 ACCEPT 的规则列表？（1 分）
（2）小明发现 IP 地址 192.168.100.20 向服务器进行了多次端口扫描，想禁止该 IP 对服务器的访问，应该如何处理？（1 分）
（3）经过一段时间，发现网段 192.168.20.0/24 内大量 IP 经常频繁对服务器进行 ping 操作，需要对该网段禁止，请问该如何处理？（1 分）
（4）公司的技术人员恰好在网段 192.168.20.0/24 内远程调试一个 Web 应用，需要允许访问服务器，该技术人员使用终端的 IP 地址为 192.168.20.115，请问该如何处理？（1 分）
（5）领导怀疑有网络测绘公司购买了服务器，频繁对服务器的 UDP 端口扫描，导致 Web 服务出口经常被测绘数据包挤占，请问该如何处理？（1 分）

参考答案与评分要点见下方解析

解析：（1）显示 INPUT 链规则
iptables -L INPUT -n --line-numbers 或 iptables -t filter -L INPUT。
说明：-L 列出规则，-n 以数字形式显示地址与端口（不做反向域名解析，速度快），--line-numbers 显示规则序号（便于后续 -D 删除）。默认表即 filter，可省略 -t filter。

（2）禁止单个 IP 访问
iptables -A INPUT -s 192.168.100.20 -j DROP
说明：-A 在 INPUT 链末尾追加，-s 指定源地址，-j DROP 静默丢弃。从安全角度用 DROP 而非 REJECT，避免向扫描者返回响应报文而暴露主机存活。

（3）禁止整个网段 ping
iptables -A INPUT -s 192.168.20.0/24 -p icmp -j DROP
说明：-s 后跟网段（CIDR 写法），-p icmp 只匹配 ICMP 协议（ping 使用 ICMP echo request）。若不加 -p icmp 会连同该网段所有流量一起封掉，可能误伤正常业务。

（4）放行网段内的单个 IP（关键：顺序陷阱）
iptables -I INPUT -s 192.168.20.115 -j ACCEPT
说明：必须用 -I 而不是 -A。因为第（3）问已经用 -A 在链尾追加了禁止 192.168.20.0/24 的 DROP 规则，iptables 规则自上而下逐条匹配、命中即止，若用 -A 追加放行规则，它会排在 DROP 之后，永远匹配不到。用 -I INPUT 把 ACCEPT 规则插到链首，才能先于 DROP 生效。若需精确指定位置可用 -I INPUT 1。

（5）限制 UDP 扫描流量
iptables -A INPUT -p udp -m limit --limit 10/s --limit-burst 20 -j ACCEPT
iptables -A INPUT -p udp -j DROP
说明：用 limit 模块限速——第一条允许 UDP 流量以每秒 10 个包的速率通过（突发上限 20 个包），第二条把超出的 UDP 包全部丢弃。两条配合既保证正常 UDP 业务（如 DNS）可用，又压制扫描流量。也可针对具体端口限制，例如 -m tcp -p tcp --dport 80 -m limit --limit 100/s。
评分要点：每题 1 分，命令中的选项（-A/-I/-s/-p/-j/-m limit）必须正确；第（4）问必须体现 -I 的插入顺序，写成 -A 不给分。

易错：第（4）问是本大题的核心陷阱：放行规则必须插在 DROP 之前，用 -I 不用 -A。第（3）问别漏 -p icmp，否则会封掉整个网段的所有流量。第（5）问必须两条规则配合（limit 放行 + 兜底 DROP）。

第 32 题（4 分）拉分

题干：小明大学毕业后进入某互联网公司担任网络管理员，负责 Linux 服务器的用户与安全管理。请回答如下问题：
（1）单位需要增加一个给技术开发部的用户账号，名字为 Wendy，密码为 $%^&，请问小明需要如何操作？（1 分）
（2）小明如果想查看 /etc/passwd 文件中关于 root 的记录，该如何操作？（1 分）
（3）小明看到 /etc/passwd 文件中显示如下内容，请问代表什么意思？（1 分）

root:x:0:0:root:/root:/bin/bash
operator:x:11:0:operator:/root:/sbin/nologin
（4）小明突然发现 /etc/passwd 文件的权限和所属用户发生了变化，请问这意味着什么？（1 分）
（5）小明赶紧打开 /etc/shadow 文件进一步查看 root 记录，请问文件中显示的如下内容分别表示什么意思？（1 分）
root:$6$zeXU7L71f1Zq7kkf$hIMuNOfqg8IVeF2BrV4T7UZhDXW4gCTLCJUQrqYNwg6EpFy4qc4ds1CJfw3ZKBfIwNWEjkmm5SrbZFzhts97Q1::0:99999:7:::

参考答案与评分要点见下方解析

解析：（1）增加用户并设置密码
useradd Wendy 创建用户（默认同时创建同名主目录 /home/Wendy 与同名用户组）。
passwd Wendy 然后按提示两次输入密码 $%^&。
也可用一条命令非交互式设置：echo '$%^&' | passwd --stdin Wendy（注意特殊字符在 shell 中需用单引号包裹，否则 $、%、& 会被 shell 解释）。

（2）查看 root 记录
grep '^root:' /etc/passwd 或 cat /etc/passwd | grep root。
用 ^root: 锚定行首可避免匹配到 rootfs、rootkit 等包含 root 的其它用户名。

（3）passwd 两行内容含义
· root:x:0:0:root:/root:/bin/bash：用户名 root；密码占位符 x（真实密码哈希在 /etc/shadow）；UID = 0（超级用户）；GID = 0（root 组）；描述信息 root；主目录 /root；登录 Shell 为 /bin/bash（可正常登录）。
· operator:x:11:0:operator:/root:/sbin/nologin：用户名 operator；密码占位符 x；UID = 11（普通用户）；GID = 0（属于 root 组）；描述 operator；主目录 /root；登录 Shell 为 /sbin/nologin——表示该账号被禁止登录系统（通常用于运行系统服务的服务账号），即使密码正确也无法获得 Shell。

（4）passwd 权限与属主变化意味着什么
/etc/passwd 的正常状态是 -rw-r--r-- 1 root root（0644），即只有 root 可写、所有人可读。
若权限变为可被普通用户写入（如 0666、0664 且属主非 root），或属主被改为其他用户，意味着：
① 系统可能已被入侵或提权成功——攻击者获得了修改用户数据库的能力；
② 普通用户可自行添加 UID 为 0 的账号，从而获得 root 权限；
③ 也可能只是管理员误操作（如执行 chmod 777 时误伤）。
应立即用 chown root:root /etc/passwd && chmod 644 /etc/passwd 恢复，并审计系统日志、检查是否有异常 UID 0 账号。

（5）shadow 一行内容含义
该行共 9 个字段（冒号分隔）：
① 用户名：root
② 加密密码：$6$zeXU7L71f1Zq7kkf$hIMuNOfq...。其中 $6$ 表示使用 SHA-512 算法；zeXU7L71f1Zq7kkf 是盐值（salt，防止彩虹表攻击）；其后的长串是密码哈希值。
③ 最后一次修改密码的日期：0，表示从 1970-01-01 起第 0 天（即该密码从未修改过）。
④ 最小修改间隔：0，表示随时可以再次修改密码，无天数限制。
⑤ 最大有效天数：99999，表示密码永不过期。
⑥ 过期前警告天数：7，表示密码到期前 7 天开始提醒用户。
⑦ 宽限天数：空，表示密码过期后不给予宽限期（立即失效）。
⑧ 账号失效日期：空，表示账号永不失效。
⑨ 保留字段：空，未使用。
评分要点：每题 1 分。（1）需含 useradd 与 passwd 两步；（3）需说明 nologin 的禁止登录含义；（4）需指出提权风险；（5）至少正确解释密码字段的算法标识与盐值、以及最大有效天数 99999。

易错：（1）密码含 $ % ^ & 等特殊字符，命令行中必须用单引号包裹，否则被 shell 展开。（3）容易漏掉 /sbin/nologin 的含义——这是服务账号禁止登录的标志。（4）不能只答「权限变了」，必须指出可被普通用户写入会导致提权。（5）shadow 是 9 个字段，容易与 passwd 的 7 个字段记混。
