第 1 讲 · 存储程序计算机与 X86 基础

CH1How the Computer Works约12分选择+填空+堆栈画图
💡 这章的逻辑主线：从"计算机凭什么能自动算"到"x86 具体怎么实现" 先立一个总原理（冯·诺依曼：指令和数据混存内存，CPU 按地址一条条取来执行），再把原理落到 x86 的具体零件上（寄存器是 CPU 的手边工作台，指令是操作，寻址是找数据），最后用"栈"演示一次真实的操作。这一章是全课的地基，后面所有内容都建立在"寄存器+内存+指令"这套模型上。

必背硬点

要点内容
冯·诺依曼原理指令和数据混存在同一存储器，CPU 作为指令解释器按地址顺序取指执行（注意：不是"程序和数据分开存"，那是反的）
8 个通用寄存器EAX 累加器(算术/返回值) · EBX 基址 · ECX 计数器 · EDX 数据 · ESI 源变址 · EDI 目的变址 · ESP 栈顶指针 · EBP 栈基指针
4 个段寄存器CS 代码段 · DS 数据段 · ES 附加段 · SS 堆栈段（存段基址，不参与算术）
EIP / EFLAGSEIP 指令指针（每执行一条自动+1，被 call/ret/jmp 改）· EFLAGS 标志寄存器
操作数宽度后缀b=8位 · w=16位 · l=32位 · q=64位（movl 搬 4 字节）
AT&T 语法指令 源, 目的（和 Intel 书面写法相反）；寄存器加 %，立即数加 $
栈向低地址增长；push 先减后写(ESP-4)、pop 先读后加(ESP+4)
⚠ 必考陷阱：ESP 指栈顶(动)、EBP 指栈基(不动)、EIP 指指令地址；段寄存器不参与算术；「冯诺依曼=程序数据分开存」是错的。
🎯 会怎么考：选择（寄存器功能/寻址方式）、填空（寄存器缩写）、程序分析题——堆栈画图 + C↔汇编互译（这章的堆栈题是 45 分大头）。

第 2 讲 · 函数调用堆栈框架

CH2How the OS Works约12分程序分析+简答
💡 这章的逻辑主线：函数一个套一个，凭什么不乱？靠栈给每个函数分一块"临时地盘" 核心矛盾：函数会互相调用、还会递归，每个函数都要存自己的参数、返回地址、局部变量——存在哪？答案是用栈：进函数时划一块地，出来时拆掉。
关键发明是 ESP/EBP 双指针：ESP 随 push/pop 一直动，用它找东西会算错；所以进函数先把 ESP 抄给 EBP 钉死（EBP 是钉墙上的锚，ESP 是随波逐流的船），之后参数、局部变量都靠 EBP 定位。call 自动记住"回来去哪"，ret 照着回去。

必背硬点

要点内容
两个指针ESP=栈顶（动态变） · EBP=栈基（函数内固定）
call / retcall：把返回地址压栈 + 跳到被调函数；ret：弹出返回地址 + 跳回
框架建立(3步)pushl %ebp → movl %esp,%ebp → subl $N,%esp（压旧基、立新基、留空间）
框架拆除(3步)movl %ebp,%esp → popl %ebp → ret（收空间、复旧基、返回）
栈上布局参数在 EBP+8(第1个)、EBP+12(第2个)；返回地址在 EBP+4；旧EBP在 EBP+0；局部变量在 EBP-4 起
传参/返回值参数用栈往里送；返回值放在 EAX
⚠ 必考陷阱：8(%ebp) 才是第1个参数（4(%ebp) 是返回地址，写错就全错）；拆除时漏掉 movl %ebp,%esp 栈会失衡。
🎯 会怎么考：程序分析题——堆栈画图、汇编转 C（占 45 分两块）；简答「简述堆栈框架建立与拆除过程」。

第 3 讲 · X86 vs ARM64 与存储层次

CH3Hardware Basics约5分选择+判断
💡 这章的逻辑主线：换个架构看差异，再往下看计算机存储怎么分层 前面讲的是 x86，这章告诉你"世界不止 x86"——ARM64 是另一大门派（手机/服务器），两者指令设计哲学不同。x86 指令变长、灵活但复杂；ARM64 指令定长、简单省电。再往下看"东西存哪"：越靠近 CPU 越快越贵越小，一层层缓存。篇幅短、事实为主，记住差异点即可。

必背硬点

对比项X86ARM64
指令长度变长（1~15 字节）固定 32 位
访问内存大部分指令都能直接访存只有 str/ldr（ST/LD）能访存
设备 I/O端口 I/O（独立端口地址空间）内存映射 I/O（像访内存一样访设备）
指令指针EIP（只能被跳转指令改）PC（只能被 b/bl/br/ret 改）

存储层次：寄存器(最快最小) → Cache → 内存 → 硬盘(最慢最大)。越近越快越贵。

🎯 会怎么考：选择/判断「x86 指令定长还是变长」「ARM 用内存映射还是端口 I/O」。

第 4 讲 · 系统调用与用户态/内核态

CH4System Call约14分简答+选择+程序分析
💡 这章的逻辑主线：用户程序不能碰内核 → 分两态 → 用系统调用"递申请" 核心矛盾：用户程序不可信，不能让它直接操作硬件/内核（否则系统崩）。解法是分两层权限：核心代码锁内核态(Ring0)，普通程序关用户态(Ring3)。用户要办事怎么办？系统调用 = 按服务铃——故意触发一个 trap 异常，主动请内核来处理。
系统调用分三层办（API 递表 → system_call 安检 → sys_xyz 科室办理），进入内核要先切权限+换内核栈+保存现场（内核不敢用用户的栈），办完 iret 返回。这章是全课最核心的机制章。

必背硬点

要点内容
两态X86：Ring3(用户)/Ring0(内核)，Linux 只用 0 和 3；ARM64：EL0(用户)/EL1(内核)
陷入/返回指令X86：int $0x80/syscall 陷入，iret/sysret 返回；ARM64：svc 陷入，eret 返回
态切换 4 动作①切权限(Ring3→Ring0) ②换栈(用户栈→内核栈) ③保存现场 ④跳处理程序
地址空间32位 Linux：用户态只能访 0x00000000~0xbfffffff，0xc0000000 以上是内核空间
三种地址逻辑地址(你写的) → 线性/虚拟地址(段页转换后) → 物理地址(内存条真实位置)
系统调用号/传参EAX 放系统调用号；参数依次放 EBX、ECX、EDX、ESI、EDI、EBP（最多6个）
三层结构API 层 xyz() → system_call 入口 → 服务例程 sys_xyz()
陷阱(trap)系统调用本质是陷阱异常（int 0x80 是向量号 128 的软中断）
⚠ 必考陷阱：态切换最易漏「切换到内核栈」；API≠系统调用（strlen 是库函数但不涉及系统调用）；用户态知道内核地址也不能直接访问。
🎯 会怎么考：简答「系统调用三层结构」「态切换发生什么」、选择（权限级/地址空间/传参）、程序分析（内嵌汇编触发系统调用）。

第 5 讲 · 嵌入式汇编

CH5Inline Assembly约6分程序分析+填空
💡 这章的逻辑主线：在 C 里插一段汇编，亲手"按一次服务铃" 上一讲讲系统调用是"按服务铃"，这章就带你亲手按一次——用 asm 在 C 里直接写汇编，把系统调用号塞进 EAX、参数塞进寄存器、执行 int $0x80。看清从 C 代码到陷入内核的完整过程。核心工具是约束符（和编译器签的"合同"：这个变量是输入还是输出、放寄存器还是内存）。

必背硬点

约束符含义
= / +=只写输出 / +读写
r / m / gr寄存器 / m内存 / g任意(编译器自选)
a/b/c/d分别指定 EAX/EBX/ECX/EDX
示例含义
time 系统调用号32位 0xd(13)；64位 0xc9(201)
rename 系统调用号0x26（旧名放 ebx、新名放 ecx）
syscall(编号, 参数...)libc 通用函数，没有现成封装的系统调用用它
⚠ 内嵌汇编题要求「逐行说语义」：movq $0,%%rax=清零累加器、addq %1,%%rax=累加输入、movq %%rax,%0=写回输出，不能只翻译助记符。操作数编号 %0 是输出、%1 起是输入。
🎯 会怎么考：程序分析题——内嵌汇编逐行分析 + 说打印结果（15 分）；填空（约束符含义、系统调用号）。

第 6 讲 · 可执行程序工作原理

CH6Principle of Executable Programs约16分 · 最重程序分析+简答+选择
💡 这章的逻辑主线：C 代码怎么一步步变成"能被系统装载运行"的程序？ 完整链路：源码 →(编译四步)→ ELF 文件 →(链接定地址)→ 可执行文件 →(fork+execve 装载)→ 跑起来。
先讲 ELF 格式（可执行文件是个"有格式的箱子"，头部是总目录、节头表是每格说明书）；再讲 编译四步（预处理展开宏/头文件 → 编译成汇编 → 汇编成机器码 → 链接拼装定地址）；链接时解决"符号解析(欠账还账)"和"重定位(改地址)"；最后 fork 分身 + execve 换脑 把它跑起来。这是篇幅最大、分值最高的一章。

必背硬点

主题内容
ELF 三类型可重定位(.o，半成品) / 可执行文件(成品) / 共享目标文件(.so，共享零件)
ELF 结构ELF Header(总目录) + 节头表(节说明书) + 程序头表(段映射)；.o 只有节头表，没有程序头表
编译四步gcc -E→.i · gcc -S→.s · gcc -c→.o · gcc a.o -o a→可执行
三大节.text 代码 · .data 已初始化全局变量 · .bss 未初始化(文件不占空间,SHT_NOBITS)
符号表/重定位表符号表=欠账清单(有定义/无定义)；重定位表=改地址引用。readelf -s看符号、-r看重定位
静态 vs 动态链接静态=买齐家具带走(大但自足)；动态=借公共家具(小但依赖)；不加 -static 默认动态
readelf/objdumpreadelf -h头 -S节头 -l程序头 -s符号 -r重定位
fork vs execvefork=分身(新PID,返回父=子PID/子=0)；execve=换脑(替换当前进程,PID不变)
内存布局栈(局部变量,向下长) · 堆(malloc,向上长) · .bss 未初始化全局 · .data 已初始化
⚠ 必考陷阱：.o 含相对地址非绝对地址、不能直接执行；.o 没程序头表；.bss 不占文件空间但占内存。
🎯 会怎么考：简答「编译四步+各产什么文件」「静态vs动态链接」、程序分析、选择（ELF类型/节的作用/fork返回值）。

第 7 讲 · 防火墙 iptables

CH7Firewall约11分25分综合题+填空
💡 这章的逻辑主线：防火墙是网络门卫，五链四表是"海关通道" 防火墙 = 站在网口的门卫，按规矩决定谁能进出。iptables 是前台工具、netfilter 是内核里真正干活的框架。
五链 = 五个关卡位置（数据包走到哪就在哪受检，回答"在哪里查"）：PREROUTING→路由判断→INPUT(给本机)/FORWARD(转发)→OUTPUT(本机发)→POSTROUTING。四表 = 每关能做的四类事（回答"能做什么"）：filter 放不放行、nat 改地址、mangle 改包细节、raw 预处理。
死穴是顺序：安检排队逐个过，前面拦下后面就不查——所以放行规则必须插到拒绝规则前面（用 -I 不用 -A）。

必背硬点

四表作用可作用链
filter过滤（默认最常用）INPUT/FORWARD/OUTPUT
nat地址转换PREROUTING/INPUT/OUTPUT/POSTROUTING（4链）
mangle改包内容(TTL/TOS)五链全可
raw连接跟踪前处理PREROUTING/OUTPUT（2链）

五链：PREROUTING 路由前 · INPUT 入站 · FORWARD 转发 · OUTPUT 出站 · POSTROUTING 路由后

语法：[iptables -t 表] 命令 链 匹配条件 -j 动作 命令：-A 追加(末尾) / -I 插入(首部) / -D 删 / -L 列表 / -F 清空 / -P 默认策略 动作：ACCEPT 放行 / DROP 静默丢弃 / REJECT 拒绝(回响应) / LOG 记录
场景命令
看INPUT规则(带序号)iptables -L INPUT -n --line-numbers
禁单个IPiptables -A INPUT -s 192.168.1.20 -j DROP
禁网段ping(保其他业务)iptables -A INPUT -s 192.168.20.0/24 -p icmp -j DROP
放行网段内单IPiptables -I INPUT -s 192.168.20.115 -j ACCEPT
UDP限速-A INPUT -p udp -m limit --limit 10/s --limit-burst 20 -j ACCEPT 再 -A INPUT -p udp -j DROP
⚠ 四大陷阱（25分综合题全在这）：①禁ping必须加-p icmp否则封全段；②放行单IP必须用-I不能用-A(命中即止,-A排在DROP后永不生效)；③用DROP不用REJECT(REJECT暴露主机存活)；④UDP限速要limit+兜底DROP两条配合。
🎯 会怎么考：25 分综合题（小明网管的 iptables 场景 5 小问）、填空（命令补全）。

第 8 讲 · 用户管理

CH8User Management约10分综合题+填空
💡 这章的逻辑主线：多人共用的系统，怎么管好"谁是谁、谁能干什么" Linux 天生多用户，管理员要把"身份"和"权限"分清楚。核心是两个文件分家：passwd 存身份信息（UID/主目录/shell，所有程序都要读，所以 0644 人人可读）；shadow 存密码哈希（不能让人读走拿去爆破，所以 0000 只有 root 能读）。身份公开，密码保密。日常就是增删改用户 + 设密码复杂度防弱口令。

必背硬点

命令作用
useradd 名 / passwd 名建账号 / 设密码
userdel -r 名 / usermod删账号含家目录(-r) / 改属性(-c描述 -L锁 -U解锁)
su - / sudo切换到某用户(要其密码) / 借权限做一件事(有日志)

/etc/passwd 七字段（0644）：用户名 : 密码占位x : UID(第3,root=0) : GID : 描述 : 主目录 : 登录Shell(/sbin/nologin=禁登录)

/etc/shadow 九字段（0000）：用户名 : 加密密码($6$=SHA-512/$5$=SHA-256/$1$=MD5) : 最后修改日 : 最小间隔 : 最大有效99999 : 警告7 : 宽限 : 失效 : 保留

密码复杂度：/etc/security/pwquality.conf（minlen 最短、minclass 字符类别数、maxrepeat 最大重复）

⚠ passwd 7 字段/ shadow 9 字段别混；密码含特殊字符命令行用单引号；passwd 权限/属主变了=入侵提权信号，要 chown root + chmod 644 恢复。
🎯 会怎么考：综合题（小明用户管理 5 小问：建号/passwd字段/nologin/shadow字段）、填空（命令、字段含义）。

第 9 讲 · 文件系统

CH9File System约9分计算题+选择
💡 这章的逻辑主线：Linux「一切皆文件」——管好文件系统就是管好整个系统 文件系统分两层：inode（索引卡，记属性和数据在哪）+ block（真正存数据）。inode 是文件身份证，但不存文件名（文件名在目录里，所以改名不改 inode）。权限是「3类人×3种权」：属主/同组/其他人，各有 r(4)w(2)x(1)。安全相关：SUID 提权风险、删除恢复（extundelete）、防恢复（srm/dd）、关键文件加锁（chattr）、SELinux 强制访问控制。

必背硬点

要点内容
权限换算r=4 w=2 x=1；rwxr-xr--=754；rw-r--r--=644；反向 755=rwxr-xr-x
特殊权限SUID(属主s位)：执行时 EUID 变文件属主；-rwsr-xr-x=4755；审计 find / -perm -4000
inode存大小/权限/属主/时间/block位置，不存文件名；stat 查看
删除恢复删除只是撕索引，数据还在；extundelete --restore-file 恢复
安全删除srm(删前覆写) / dd if=/dev/random of=设备 覆写整个分区
磁盘分区→格式化→挂载；df看文件系统 / du看目录 / lsblk看设备
MBR最多 4 个主分区；不够用"扩展分区"里再切"逻辑分区"
加锁chattr +i只读锁 / +a只能追加；lsattr 查看；连 root 都要解锁
SELinux给进程和文件打标签，标签匹配才放行；三模式 Disabled / Permissive(只告警) / Enforcing(真拦)
⚠ 算 rws 时 s 在 x 位该段仍算 1 分，再额外加特殊位 4（别把 -rwsr-xr-- 算成 0755）。
🎯 会怎么考：计算题（权限串↔数字互换 + SUID）、选择（inode/特殊权限/SELinux模式）。

第 10 讲 · 安全扫描工具

CH10Security Scanning Tools约3分填空+选择
💡 这章的逻辑主线：渗透第一步是"踩点"——先摸清门在哪、门后是什么 攻击前先侦察：目标开了哪些门（端口）、门后是什么服务、有没有漏洞。端口是服务的"门牌号"，记住常见端口就能一眼看出开了什么服务。nmap=慢而准的瑞士军刀，masscan=快而糙的扫描枪，nikto=专查Web，OpenVAS=综合体检。分值低，重点记端口和工具参数。

第 11 讲 · 系统诊断

CH11System Diagnosis约2分选择+判断
💡 这章的逻辑主线：防火墙是门卫（拦），IDS 是监控（看有没有人翻墙进来） 门卫拦不住所有花招，所以需要入侵检测(IDS)来监控。按"看哪里"分：NIDS 看全网流量(网络节点)、HIDS 看单台主机(文件/进程/日志)。IDS 只喊、IPS 直接拦。还有几件配套武器：蜜罐(诱饵机，引黑客来并记录)、Rootkit 检测(Chkrootkit/Rkhunter)、威胁情报(坏人资料库)、杀毒(ClamAV)。分值最低，记住分类和工具名。

必背硬点

要点内容
IDS 分类NIDS 网络型(装在网络节点看流量) / HIDS 主机型(装单机看文件进程日志)
IDS vs IPSIDS 只检测告警；IPS 直接阻断（串在链路中间 inline）
蜜罐 KippoSSH 蜜罐，诱骗黑客登录并记录全程操作
Rootkit 检测Chkrootkit / Rkhunter（木马=伪装好人，Rootkit=潜伏隐藏的高级木马）
