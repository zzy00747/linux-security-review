3.1 X86 与 ARM64 架构差异页1页2页3页1

💡 一句话逻辑：x86 和 ARM64 是两个门派：x86 指令长短不一、灵活但复杂（电脑用）；ARM64 指令整齐划一、简单省电（手机用）。理解差异才懂为什么程序不能跨平台直接跑。

Hook：同样一句 C 语言的函数调用，在笔记本上和在手机上编译出的机器码完全不同。两大指令集的分歧点，其实只有三个。

X86 与 ARM64 的三大差异：访问内存的指令范围（X86 大多数指令可直接访问内存，ARM64 只有 str/ldr 及其变种）、指令编码长度（X86 变长、ARM64 固定 32 比特）、以及跳转指令的名称（X86 用 call/ret/jmp，ARM64 用 b/bl/br/blr/ret）；两者共同点是指令指针寄存器都不能被直接修改。

Why：这三个差异直接决定了两种平台的汇编长相。X86 变长编码让指令更紧凑、寻址方式更丰富，但取指译码复杂；ARM64 定长 32 比特让流水线简单、功耗低，代价是每条指令能表达的信息更少，所以必须把「算」和「访存」严格分开——这就是为什么 ARM64 只有 ldr/str 能碰内存。理解这一点，你看到 ARM64 汇编里先 ldr 再 add 的两步操作就不会觉得啰嗦。

What：① 访问内存：X86 大多数指令可以直接访问内存；ARM64 中只有 str/ldr（ST/LD）及其变种指令可以访问内存。② 指令编码：X86 指令的编码长度不是固定不变的，指令指针寄存器自动加「一」，这里的「一」不是一个固定字节长度，而是智能地加一条指令的长度；ARM64 中指令编码长度固定为 32 比特。③ 跳转指令：X86 为 call、ret、jmp 等；ARM64 为 b、bl、br、blr 和 ret 等。

访问内存的指令大多数指令可直接访问内存只有 str/ldr 及其变种

跳转/调用指令call、ret、jmpb、bl、br、blr、ret

How：把 C 语言结构映射到指令：编译器将 C 语言中的函数调用、return 和 if-else 语句映射为这些跳转指令——函数调用在 X86 上是 call、ARM64 上是 bl；return 两边都是 ret；if-else 在 X86 上是条件跳转（jmp 家族）、ARM64 上是 b 家族的条件形式。特别注意讲义强调的一点：指令指针寄存器在 X86 和 ARM64 中都不能被直接修改，它只能被跳转类指令修改。这条约束是体系结构层面的硬规则，也是为什么攻击者无法用一条 mov 直接改 EIP、必须借助 ret 或 jmp 类指令完成控制流劫持的根本原因。

易错：以为 ARM64 的「固定 32 比特」意味着所有指令功能一样。定长指的是编码宽度固定，指令语义仍然千差万别；另外别把 X86 的 eip 自动加「一」理解成加 1 个字节，讲义明确说这个「一」是一条指令的长度。

3.2 存储层次与总线结构页4页5页6页7页8页4

💡 一句话逻辑：存储像三层书架：手边抽屉(寄存器，快而贵) → 旁边书架(内存，中等) → 远处图书馆(硬盘，大而慢)。越近越快越贵，所以要一层层缓存。

Hook：CPU 主频几个 GHz，内存却要几十纳秒才回一次数据。这么慢的搭档，怎么没把 CPU 拖死？答案藏在一条从寄存器到硬盘的「金字塔」里。

计算机存储系统是层次结构，越靠近 CPU 越快越小越贵；而 CPU 与内存、设备之间靠总线连接——处理器接口因为可以挂载多个设备和内存芯片，这种特性使其被称为「总线」。

Why：速度、容量、成本三者不可兼得，唯一的出路是分层：用极小极快的寄存器与缓存承接热点数据，用大而慢的内存与磁盘存放全量数据，让绝大多数访问落在快的那一层。而总线则是这套层次的物理通道——所有层次的部件都挂在同一组导线上，靠地址来区分彼此。

What：存储系统层次结构：从快到慢、从小容量到大容量依次是 CPU 寄存器、高速缓存（Cache）、主存（内存）、外存（磁盘）。总线（Bus）：有些设备像内存芯片一样连接到处理器接口上，处理器接口这种可以挂载多个设备和内存芯片的特性使其被称之为「总线」。32 位 CPU 与内存之间用地址总线、数据总线和控制总线连接，每条线上有 1 和 0 两种状态。

How：以「从内存读一个数到寄存器」走一遍完整流程：① CPU 通过控制总线 RD 发一个读请求，并且将内存地址通过地址总线 A0–A31 发给内存；② 内存芯片收到地址和读请求之后，将相应的内存单元对接到数据总线 D0–D31；③ 这样内存单元每一位的 1 或 0 状态通过一条数据线到达 CPU 寄存器中相应的位，就完成了数据传送。注意三条总线的分工不能混：地址总线是单向的（CPU 指出「要哪一格」），数据总线是双向的（内容来回走），控制总线传命令（读还是写）。32 根地址线意味着可寻址 $2^{32}$ 个字节即 4GB 空间，32 根数据线意味着一次可搬运 4 字节——这正是 32 位平台 4GB 寻址上限的物理来源。

易错：把「总线」当成一种具体设备。总线是一组共享的导线与协议，所有挂在上面的设备分时复用；也别忘了地址总线宽度直接决定了寻址空间大小。

重点

3.3 总线设备、设备寄存器与内存映射 I/O 及端口 I/O页9页10页11页9

💡 一句话逻辑：CPU 怎么和外设说话？两种方式：给设备编个"内存地址"，像访问内存一样访问它（内存映射 I/O，ARM 用）；或单独编"端口号"（端口 I/O，x86 特有）。

Hook：你往一个地址写了个 1，内存里什么也没变，但风扇突然转快了。为什么「写内存」能控制硬件？

总线上的设备与内存芯片占用不同的地址范围，访问设备就像访问内存一样按地址读写；但语义不同——写只是发命令、数据不一定保存，读得到的是设备当前状态。设备内部可供读写的存储单元叫设备寄存器（与 CPU 寄存器不是一回事）。操作方式分两种：内存映射 I/O（Memory-mapped I/O，如 ARM）与 端口 I/O（Port I/O，X86 专用，用 in/out 指令）。

Why：CPU 只会「按地址读写」，它不懂什么是网卡、什么是硬盘。要让 CPU 控制设备，最省事的办法就是把设备的控制单元也编进地址空间——于是同一个 mov 指令既能改内存也能改硬件。但设备的存储单元不是普通内存：它不是存储介质而是控制面板，所以读写语义必须重新定义，否则程序员会误以为写进去的值下次还能读出来。

What：① 总线上的设备：很多设备和内存一样直接通过总线和 CPU 相连，它们与内存芯片占用不同的地址范围。② 与访问内存的差异：往一个地址写数据只是给设备发一个命令，数据不一定要保存；从一个地址读数据也不一定是读先前保存在这个地址的数据，而是得到设备的当前状态。③ 设备寄存器：总线上的设备也具有可供读写访问的存储单元，通常称为设备寄存器；设备芯片是专用微型处理器，和通用处理器 CPU 一样内部包含一些存储单元，为了与 CPU 寄存器做区分才称之为设备寄存器。④ 两种 I/O 方式：内存映射 I/O 与端口 I/O。

对比项内存映射 I/O端口 I/O
典型体系结构ARM 等多数体系结构X86 专用
地址空间与内存共用同一地址空间独立的端口地址空间
访问指令与访问内存相同的指令特殊的 in/out 指令
连接方式通过普通地址线寻址CPU 核引出额外的地址线

How：先看共同点：无论是在 CPU 外部接总线的设备，还是集成在处理器芯片内部的设备，都有各自的地址范围，都可以像访问内存一样访问。再看 X86 的特殊之处：X86 对于设备有独立的端口地址空间，CPU 核需要引出额外的地址线来连接处理器芯片内部集成的设备，和访问内存所用的地址总线不同；访问设备寄存器时用特殊的 in/out 指令，而不是和访问内存用同样的指令，这种方式称为端口 I/O。一句话记忆：ARM 走「同一条路、同一个指令」，X86 走「另开一条路、专用指令」。这也解释了为什么写驱动时 ARM 平台直接对地址赋值，而 X86 平台要用 inb/outb 这类函数——它们最终编译成 in/out 指令。

易错：把设备寄存器当成 CPU 寄存器。设备寄存器在设备芯片内部、通过总线按地址访问；CPU 寄存器在 CPU 内部、由指令名直接引用。另外别以为「写设备地址」等于「存数据」——它往往只是发一条命令，回读得到的通常是状态而非原值。

必考

问题一：以 32 位 CPU 从内存读一个数到寄存器为例，说明地址总线、数据总线、控制总线各自承担什么角色，并指出为什么 32 根地址线决定了 4GB 的寻址上限。
参考答案CPU 先通过控制总线发出 RD 读请求，同时把要访问的内存地址经地址总线 A0–A31 送给内存；内存芯片收到地址与读请求后，把对应内存单元对接到数据总线 D0–D31；该单元每一位的 1 或 0 状态沿各自的数据线传送到 CPU 寄存器的相应位，传送完成。三条总线分工是：地址总线单向指出「哪一格」，数据总线双向搬运内容，控制总线传递读/写等命令。32 根地址线每根有 0/1 两种状态，可组合出 $2^{32}$ 个不同地址，按字节编址即 4GB，因此 32 位平台的内存寻址上限是 4GB；同理 32 根数据线意味着一次可并行搬运 32 位即 4 字节。
问题二：为什么说「访问总线上的设备就像访问内存一样，但语义不同」？请分别说明写操作与读操作在设备地址上的真实含义，并指出 X86 与 ARM 在访问设备方式上的关键区别。
参考答案相同之处在于设备与内存芯片占用不同的地址范围，CPU 都通过总线按地址访问，形式上都是读写某个地址。语义差异在于：往设备地址写数据只是给设备发一个命令，数据不一定要保存下来；从设备地址读数据也不一定是读先前写入该地址的值，而是得到设备的当前状态。原因是这些存储单元是设备寄存器——设备芯片作为专用微型处理器内部的存储单元，用于控制而非存储数据，与 CPU 寄存器不是一回事。关键区别在访问通道与指令：ARM 等多数体系结构采用内存映射 I/O，设备与内存共用地址空间、用与访问内存相同的指令；X86 采用端口 I/O，设备拥有独立的端口地址空间，CPU 核需引出额外地址线，并用特殊的 in/out 指令访问设备寄存器。
