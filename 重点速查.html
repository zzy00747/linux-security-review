一、要点一 · 内核分析（约 55–60 分）

1.1 常用寄存器（要点一第1条）必背

💡 先讲逻辑：寄存器是 CPU 的"手边工作台" CPU 算东西，数据放哪？内存虽然大但太远（慢），寄存器就在 CPU 手边（快）。所以正在算的数、下一条指令在哪、栈顶在哪，统统放寄存器。
为什么不搞一个万能寄存器？分工效率最高：EAX 是算术主力（加减乘除、存返回值），ECX 天生会数数（循环计数），ESP/EBP 是栈的两个定位针（一个指栈顶、一个指栈基），EIP 永远指着下一条要执行的指令——程序能一句句往下跑，全靠 EIP 每步自动 +1。
段寄存器（CS/DS/ES/SS）不一样，它们像"分区管理员"，只负责告诉你"哪一段内存"，不参与算术。
32位16位8位(高/低)名称主要用途
EAXAXAH / AL累加器算术运算、函数返回值、系统调用号（32位）
EBXBXBH / BL基址寄存器存放内存基址
ECXCXCH / CL计数器循环计数、字符串操作
EDXDXDH / DL数据寄存器乘除法辅助、I/O 端口
ESISI—源变址字符串/数组源地址
EDIDI—目的变址字符串/数组目的地址
ESPSP—栈指针始终指向栈顶，push 减4/pop 加4
EBPBP—基址指针指向当前函数栈框架基址
EIPIP—指令指针下一条指令地址，每条指令后自动递增
EFLAGSFLAGS—标志寄存器ZF/CF/SF/OF 等状态位
段寄存器全称存放内容
CSCode Segment代码段基址（配合 CS:EIP 定位指令）
DSData Segment数据段基址
ESExtra Segment附加数据段基址
SSStack Segment堆栈段基址
⚠ 必考陷阱：ESP 指栈顶（动态变），EBP 指栈基（函数内固定）；EIP 是指令地址不是栈地址。段寄存器不参与算术运算。

1.2 寻址方式与常用指令（要点一第2条）重点

💡 先讲逻辑：CPU 拿数据有几种"报地址"的方式 你要 CPU 算一个数，得告诉它数在哪——这就是寻址。最简单：直接给地址（立即数 $8）；用寄存器里的值当地址；寄存器+偏移（8(%ebp)=EBP 再加 8 个字节的位置）。
最关键一条：AT&T 语法是「源在前、目的在后」（movl %esp,%ebp 是把 esp 的值给 ebp），和 Intel 书面写法正好反过来。记住这个顺序，转 C 题就不会把方向搞错。

AT&T 语法：指令 源, 目的；寄存器加 %，立即数加 $。

后缀宽度示例
b8 位（byte）movb
w16 位（word）movw
l32 位（long）movl / pushl / popl / addl / subl
q64 位（quad）movq / addq
写法含义用途
8(%ebp)EBP+8 处内存取第1个函数参数（EBP+4 是返回地址）
-4(%ebp)EBP-4 处内存取局部变量
(%esp)ESP 指向处栈顶（刚 push 的实参）
$8立即数 8常量

常用指令：mov传送 / push压栈 / pop出栈 / add加 / sub减 / call调用 / ret返回 / lea取地址 / jmp跳转。X86 指令变长，ARM64 固定 32 位。

1.3 堆栈画图 + 汇编转 C（要点一第3条 · 程序分析题核心）必考

💡 先讲逻辑：栈是个"从天花板往下堆箱子"的架子 内存地址是从高往低用的——想象栈顶在天花板，你往上放箱子，越堆越低，所以叫"栈向低地址增长"。
push = 放箱子：先把位置往下挪 4 格（ESP-4），再把东西放进去（先减后写）。
pop = 拿箱子：先把东西拿起来（读 ESP 处），再把位置往上挪 4 格（先读后加）。
addl $4,%esp 只是把"手指"往上挪，箱子还在原处没搬走——这就是"数据仍残留"的原因（也是取证能读到已删数据的原因）。
汇编转 C 就是反着读：看哪里取参数（8(%ebp)）、看做了什么运算（addl）、看调了谁（call）。

① 堆栈画图 —— 逐步推演

push $8 → ESP 先减 4 再写 8 movl %esp,%ebp → EBP = ESP（覆盖原值） pushl %ebp → ESP 减 4，写入旧 EBP 的值 pushl $8 → ESP 减 4，写入 8 addl $4,%esp → ESP 加 4（只改指针，不清内存） popl %ebp → 先读 ESP 处值给 EBP，再 ESP 加 4
⚠ 三条铁律：push 先减后写、pop 先读后加；addl $4,%esp 只抬栈顶不清数据；movl %esp,%ebp 会覆盖 EBP 原值。

② 汇编转 C —— 三看口诀

看什么怎么判断
看参数8(%ebp) 是第1个参数，12(%ebp) 是第2个
看运算addl $3,%eax → 参数 +3；addl $1,%eax → 返回值 +1
看调用subl $4,%esp + movl %eax,(%esp) + call g → g(参数)；call 后紧跟 addl → 返回值继续参与运算
✔ 典型答案：g: return x+3; / f: return g(x); / main: return f(8)+1;

1.4 函数调用堆栈框架五步（要点一第4条）必背

💡 先讲逻辑：为什么要 EBP？——因为 ESP 一直在动，得钉个锚 函数执行时，ESP 每 push 一个局部变量、每调一次子函数就变一次。如果用 ESP 找参数（"参数在 ESP+8"），那 ESP 一动偏移就错，你根本算不准参数在哪。
所以聪明做法：进函数第一件事，把 ESP 抄一份给 EBP 钉死。之后不管 ESP 怎么上下，参数永远是 EBP+8、局部变量永远是 EBP-4——因为 EBP 从没动过。
一句话：EBP 是钉在墙上的锚，ESP 是随波逐流的船。离开函数时再把 ESP 拉回 EBP（一次性丢掉所有局部变量），锚也就收走了。

建立（进函数，3 步）：

① pushl %ebp ; 保存调用者 EBP（锚要留个底） ② movl %esp, %ebp ; 把 ESP 抄给 EBP → 立新锚 ③ subl $N, %esp ; 给局部变量腾 N 字节空间

拆除（返回前，3 步）：

④ movl %ebp, %esp ; ESP 拉回锚点，一次性丢掉局部变量 ⑤ popl %ebp ; 恢复调用者的旧锚 ⑥ ret ; 弹出返回地址并跳转回去
口诀：「压旧基、立新基、留空间 → 收空间、复旧基、返回」。参数在 EBP+8 起，局部变量在 EBP-4 起。
⚠ 顺序不能乱：先 push ebp 再 mov esp,ebp；拆除先 mov ebp,esp 再 pop ebp。漏掉第④步栈会失衡。

1.5 嵌入式汇编语法与约束符（要点一第5条）必背

💡 先讲逻辑：约束符是你和编译器的"合同" 你在 C 里插一段汇编，编译器不知道你的变量该放哪、是输入还是输出。约束符就是这份合同：
"=m"(val3) 意思是"val3 是输出（=），放内存（m），我汇编执行完会把结果写进去，你（编译器）别乱安排"。
"g"(val1) 意思是"val1 是输入，你随便放寄存器或内存都行（g=general）"。
记住：= 输出、+ 读写、r 寄存器、m 内存、g 随便。操作数编号 %0 是第一个输出、%1 起是输入。

语法：asm volatile("指令" : 输出 : 输入 : 破坏列表);

约束符含义记忆
=只写的输出操作数等号=输出
+既读又写的操作数加号=读写
r通用寄存器r = register
m内存操作数m = memory
g通用（寄存器或内存皆可，编译器自选）g = general
i / n立即数（i：0~31，n：立即数）i = immediate
a/b/c/d分别指定 EAX/EBX/ECX/EDX字母对应寄存器
⚠ 内嵌汇编题必考「逐行说明作用」，要说出语义不是翻译助记符：movq $0,%%rax=清零累加器；addq %1,%%rax=累加第1个输入；movq %%rax,%0=结果写回输出。

1.6 系统调用三层结构（要点一第6条）必考

💡 先讲逻辑：用户程序不能直接进内核，得像去政府办事一样过安检 为什么不能直接调内核函数？因为用户程序不可信——万一你写个死循环或恶意代码在内核里跑，整个系统就崩了。
所以要过三道流程：
① xyz() API 层 = 去办事窗口领表（glibc 帮你把参数摆好）；
② system_call 入口 = 安检+登记（保存现场、查系统调用表，决定找哪个科室）；
③ sys_xyz() 服务例程 = 具体科室真正把事办完。
用户程序永远碰不到内核代码，只能"递申请"。
用户程序 → API 层 xyz() （如 time()、fork()，glibc 封装） ↓ 陷入（int $0x80 / syscall） 系统调用入口 system_call / entry_SYSCALL_64 ↓ 按系统调用号查表分发 服务例程 sys_xyz() （内核态实际干活）
层作用
xyz() API 层用户可见的库函数，把参数放寄存器、执行陷入指令、取回返回值
system_call 入口层保存现场、按系统调用号查系统调用表、分发、恢复现场返回
sys_xyz() 服务例程内核态完成实际功能
⚠ API 与系统调用不是一一对应：fork 一个 API 对应一个系统调用；strlen 是库函数但不涉及系统调用；printf 一个 API 可能封装 write 等多个系统调用。

1.7 态切换时发生什么（要点一第7条）重点

💡 先讲逻辑：为什么要"换栈"？——内核不敢用用户的栈 用户态和内核态用的是两个不同的栈。用户栈是"你的地盘"，可能被你的程序破坏或恶意构造；内核不能信任它，所以进门（进内核）时立刻换用内核自己的栈——这样内核干活才安全。
这就是态切换最容易被漏答的关键动作：切权限（Ring3→Ring0）+ 换栈（用户栈→内核栈）+ 保存现场 + 跳处理程序。回来时用 iret 把现场恢复、权限退回用户态。
架构权限级用户态/内核态陷入指令返回指令
X86Ring 0~3Ring3 / Ring0（Linux 只用 0 和 3）int $0x80 / syscalliret / sysret
ARM64EL0~EL3EL0 / EL1svceret
① 权限级切换：Ring3 → Ring0 ② 【关键】切换栈：用户栈 → 内核栈（每种态各自的栈！） ③ 保存现场：压入 SS/ESP/EFLAGS/CS/EIP 到内核栈 ④ 查中断向量表跳处理程序；返回时 iret 恢复现场
⚠ 最容易漏答「切换到内核栈」。地址空间：32位 Linux 用户态只能访问 0x00000000~0xbfffffff，0xc0000000 以上是内核空间。

1.8 编译四步 + 内存布局（要点一第9条）必考

💡 先讲逻辑：把"人话"翻译成"机器 0/1"要分几道工序 你写的 C 是给人看的，CPU 只认 0/1。中间要过几道工序：
预处理=把 #define 宏和 #include 的文件文本替换展开（还是 C，只是变长了）；
编译=翻译成汇编（人类还能读的机器指令）；
汇编=汇编翻成 0/1 机器码（.o）；
链接=把多个 .o 和库拼成一个完整程序，并把地址都定下来。
内存布局的逻辑：能自动回收的临时变量放栈；手动申请的放堆；未初始化的全局变量放 .bss（反正初值都是 0，文件里不用真的存一堆 0）。
步骤命令产物做什么
预处理gcc -E a.c -o a.i.i删注释、展开宏、插入 #include
编译gcc -S a.i -o a.s.s翻译成汇编语言
汇编gcc -c a.s -o a.o.o翻译成机器码（已是 ELF）
链接gcc a.o -o a可执行文件符号解析 + 重定位定地址
区域存放内容特性
栈 stack局部变量、函数参数、返回地址系统自动分配释放，向低地址增长
堆 heapmalloc/new 动态申请程序员手动管理，向高地址增长
.bss未初始化的全局/静态变量文件里不占空间（SHT_NOBITS），运行时清零
.data已初始化的全局/静态变量占文件空间
.text机器指令通常只读

readelf / objdump：readelf -h文件头 / -S节头 / -l程序头(段表) / -s符号表 / -r重定位。ELF 三种：可重定位(.o) / 可执行 / 共享库(.so)；程序头表只在可执行文件和 .so 有，.o 没有。

1.9 进程描述符 + fork（要点一第10条 · 教材6.1/6.2）必考

💡 先讲逻辑：fork 是"分身术"，返回值是分身的身份证 fork() 让当前进程复制出一个分身。父子俩从同一个点继续往下跑，长得一模一样——那怎么知道自己是谁？
靠返回值：父进程拿到"孩子的身份证号"（子 PID，>0），子进程拿到 0（"我是孩子，没有孩子"）。所以 if(pid==0) 就是"我是子进程"的分支。
task_struct 是内核记录每个进程的"档案袋"，里面存 PID、父子关系、打开的文件、地址空间等。

进程描述符 task_struct：内核描述进程的结构体，含 PID、状态、父子进程指针、打开文件表、地址空间。

fork() 返回含义
父进程返回子进程 PID（>0）父进程据此知道子进程编号
子进程返回 0子进程据此识别「我是子」
失败返回 -1创建失败

fork vs execve：fork 创建新进程（PID 变），execve 替换当前进程映像（PID 不变）。

⚠ 陷阱：else if ((pid=fork()) < 0) 这个分支正常永不执行（fork 成功只返回 >0 或 0）。画进程树时 else-if 链命中即跳出，一个进程只走一个分支，别把整条链的 printf 都算给同一进程。

二、要点二 · 系统安全（约 40–45 分）

2.1 iptables 四表五链（要点二第1条）必考 25分综合题

💡 先讲逻辑：数据包走"海关通道"，五链是关卡、四表是每关能做的事 想象数据包是"人"，从网卡进来到离开，要走一条固定的海关通道：
入境口(PREROUTING) → 判断去哪 → 本地居民走 INPUT / 过境旅客走 FORWARD → 出境口(POSTROUTING)，本地人寄东西走 OUTPUT。
「链」= 五个关卡位置，回答「在哪里查」；「表」= 每个关卡能做的四类事，回答「能做什么」：
· filter=放不放行（安检说"过"或"不过"，最常用）
· nat=改地址（换护照上的门牌号，改源/目的 IP）
· mangle=改包的细节（改 TTL 之类的外包装）
· raw=最前置的预处理（正式检查前先动手脚）
为什么链的顺序是死穴：安检是排队逐个过，前面被拦下后面根本不查。所以你若先设"整个网段 DROP"，再加"She 的 IP ACCEPT"，She 仍会被前面那条 DROP 拦下——因为她排在后面永远轮不到。放行必须插到拒绝前面（用 -I 不用 -A），这就是 25 分题的核心。
表作用可作用链
filter过滤（最常用，默认表）INPUT / FORWARD / OUTPUT
nat地址转换PREROUTING / INPUT / OUTPUT / POSTROUTING
mangle修改数据包内容（TTL/TOS）五链全可
raw连接跟踪前处理PREROUTING / OUTPUT

五链：PREROUTING路由前 → INPUT入站(给本机) → FORWARD转发(给别人) → OUTPUT出站(本机发) → POSTROUTING路由后

iptables [-t 表] 命令 链 匹配条件 -j 动作 命令：-A 追加(末尾) / -I 插入(默认首部) / -D 删除 / -L 列表 / -F 清空 / -P 默认策略 动作：ACCEPT 放行 / DROP 静默丢弃 / REJECT 拒绝(返回响应) / LOG 记录
场景命令
看 INPUT 规则（带序号）iptables -L INPUT -n --line-numbers
禁单个 IPiptables -A INPUT -s 192.168.1.20 -j DROP
禁网段 ping（保留其他业务）iptables -A INPUT -s 192.168.20.0/24 -p icmp -j DROP
放行网段内单个 IPiptables -I INPUT -s 192.168.20.115 -j ACCEPT
UDP 限速-A INPUT -p udp -m limit --limit 10/s --limit-burst 20 -j ACCEPT 再 -A INPUT -p udp -j DROP
⚠ 四大陷阱（25分综合题全在这）：
① 禁 ping 必须加 -p icmp，否则封掉整个网段所有流量；
② 放行单个 IP 必须用 -I 不能用 -A——规则自上而下、命中即止，-A 追加的放行排在 DROP 后永远不生效；
③ 用 DROP 不用 REJECT——REJECT 会返回响应暴露主机存活；
④ UDP 限速必须 limit + 兜底 DROP 两条配合。

2.2 用户管理 passwd / shadow（要点二第2条）必背

💡 先讲逻辑：passwd 和 shadow 为什么要分家？ /etc/passwd 存 UID、主目录、登录 shell，这些所有程序都要读（ls 显示文件属主要查它、登录程序要查你的主目录），所以它必须人人可读（0644）。
但密码哈希绝不能让人随便读走——拿到哈希就能拿去离线爆破。所以把密码单独放 /etc/shadow，只有 root 能读（0000）。
一句话：身份信息（passwd）公开，密码（shadow）保密。这就是两个文件分家的逻辑。
也因此——passwd 的权限/属主一旦变成别人可写，就说明有人能自己加个 UID=0 的号来提权，是被入侵的信号。

/etc/passwd 七字段（默认权限 0644）：

#字段示例 root:x:0:0:root:/root:/bin/bash
1用户名root
2密码占位符x（真实密码在 shadow）
3UID0（root 的 UID 是 0）
4GID0
5描述信息root
6主目录/root
7登录 Shell/bin/bash（/sbin/nologin 表示禁止登录）

/etc/shadow 九字段（默认权限 0000）：

#字段说明（示例 $6$...::0:99999:7:::）
1用户名root
2加密密码$6$=SHA-512、$5$=SHA-256、$1$=MD5；$ 之间是盐值
3最后修改日0（从 1970-1-1 起第 0 天）
4最小间隔0（随时可改）
5最大有效天数99999（永不过期）
6警告天数7（到期前 7 天提醒）
7宽限天数空（过期即失效）
8失效日期空（永不失效）
9保留空

命令：useradd wendy建 / passwd wendy设密码 / userdel -r删及家目录 / usermod -c改描述 -L锁 -U解锁 / su -切换 / sudo提权。复杂度配置：/etc/security/pwquality.conf（minlen/minclass/maxrepeat）。

⚠ passwd 7 字段、shadow 9 字段别记混。密码含 $%^& 等特殊字符时命令行要用单引号。权限/属主变了要 chown root:root && chmod 644/000 恢复。

2.3 inode 与权限换算（要点二第3条）必考计算

💡 先讲逻辑：文件权限为什么是"3 类人 × 3 种权"？ 一个文件要管住三种人：属主（自己）、同组人、其他人。每种人能做的事就三种：读(r)、写(w)、执行(x)。所以正好「3 类人 × 3 种权」= 9 位，三位一组。
为什么数字是 4/2/1？因为每一位就是个开关：r=4、w=2、x=1，三个开关全开 4+2+1=7。所以 rwx=7、r-x=5、r--=4。
inode 是文件的"身份证"——存大小、权限、属主、数据在哪，但偏偏不存文件名（文件名在目录里，目录负责"名字 → inode 号"的映射，所以改名不改 inode）。

inode 存大小、权限、属主、时间戳、block 位置……但不存文件名。stat 查看。

权限 10 位：-rwxr-xr-- = 类型(1)+属主(3)+组(3)+其他(3)。类型 -普通 d目录 l链接。

权限位数字说明
r4读
w2写
x1执行
-0无

换算范例：rwxr-xr-- → 7 / 5 / 4 → 754；反向 644 → rw- r-- r--。

特殊权限：SUID（属主执行位变 s）：执行时 EUID 变为文件属主，如 -rwsr-xr-x=4755。/usr/bin/passwd 就是 root 的 SUID，被利用可提权。审计：find / -perm -4000 -type f。

⚠ 算 rws 时：s 在 x 位置该段仍算 1 分（执行位有效），再额外加特殊位 4。别把 -rwsr-xr-- 算成 0755。

2.4 扫描工具（要点二第4条）高频

💡 先讲逻辑：渗透第一步是"踩点"——先摸清门在哪 攻击前要先侦察：目标开了哪些门（端口）、门后是什么服务、有没有漏洞。就像小偷先踩点看哪扇窗没关。
nmap=慢而准的瑞士军刀（探活+扫端口+认服务）；masscan=快而糙的扫描枪（大网段扫得快，靠"发完就跑"）；nikto=专查 Web 服务器；OpenVAS=综合体检（5 万+ 项检查）。
工具用途关键选项
nmap主机发现+端口扫描+服务识别-sn只探活、-sTTCP连接、-sSSYN半开、-sUUDP、-sV服务版本、-p1-65535全端口
masscan高速大网段扫描（异步无状态）-p1-100 --rate=10000
niktoWeb 服务器漏洞扫描-h 目标 -c 目录
OpenVAS综合漏洞扫描系统（50000+ 测试）C/S 架构
SQLMapSQL 注入自动检测与利用支持 MySQL/Oracle/PG 等

常见端口：SSH 22 / Telnet 23 / FTP 21 / HTTP 80 / HTTPS 443 / RDP 3389 / MySQL 3306 / Tomcat 8080 / NFS 2049。端口范围 0~65535。

⚠ UDP 是无连接协议，UDP 端口扫描可靠性低（没有 3 次握手，只能靠超时判断）。nmap 只探活用 -sn。

三、三道程序分析题模板（45 分 · 一定要手写一遍）

💡 先讲逻辑：这三道题就是老师例题原题，套路固定 程序分析题看着吓人，其实是三个固定套路：内嵌汇编（逐行说语义）、汇编转C（三看：参数/运算/调用）、堆栈画图（push 先减后写、pop 先读后加）。自己动笔推一遍，比看十遍都强——考试就是换个数字让你推。

模板 A · 内嵌汇编逐行分析（15 分）

答题格式：每行 = 指令字面 + 语义动作（说"干什么"，不能只翻译）

movq $0,%%rax → 把立即数 0 送入 rax，清零累加器 addq %1,%%rax → 把第1个输入 (val1) 累加到 rax addq %2,%%rax → 把第2个输入 (val2) 累加到 rax movq %%rax,%0 → 把结果写回第0个输出 (val3) 约束 "=m"(val3) → val3 是只写输出，位于内存 约束 "g"(val1) → val1 由编译器自由分配寄存器或内存 最终 val3 = 0+1+2 = 3 → 打印 val1:1+val2:2=val3:3

模板 B · 汇编转 C（15 分）

三看口诀：参数看 8(%ebp)、运算看 addl 立即数、调用看 call 前后。

g: movl 8(%ebp),%eax ; addl $3,%eax ; ret → int g(int x){ return x+3; } f: subl $4,%esp ; movl 8(%ebp),%eax ; movl %eax,(%esp) ; call g → int f(int x){ return g(x); } main: movl $8,(%esp) ; call f ; addl $1,%eax → int main(void){ return f(8)+1; }
为什么 8(%ebp)：栈布局是「实参 → 返回地址(4) → 旧EBP(4)」，所以 0(%ebp)=旧EBP、4(%ebp)=返回地址、8(%ebp)=第1个参数。写 4(%ebp) 取到的是返回地址就错了。

模板 C · 堆栈画图（15 分）

设初始 ESP=0x1000，逐条推（push 先减后写、pop 先读后加）：

指令ESP 变化内存动作
pushl $80x1000→0x0FFC[0x0FFC]=8
movl %esp,%ebp不变EBP=0x0FFC
pushl %ebp0x0FFC→0x0FF8[0x0FF8]=0x0FFC
pushl $80x0FF8→0x0FF4[0x0FF4]=8
addl $4,%esp0x0FF4→0x0FF8只抬栈顶，[0x0FF4] 数据仍在
popl %ebp0x0FF8→0x0FFCEBP=[0x0FF8]=0x0FFC

最终：ESP=EBP=0x0FFC（重合），[0x0FFC]=8、[0x0FF8]=0x0FFC、[0x0FF4]=8（残留）。

四、判断题高频陷阱（10 分，白送别白丢）

💡 先讲逻辑：判断题的套路只有一个——绝对化表述 出题人想让你判"错"，最爱的就是塞「只有」「一定」「都能」「都含」「不需要」这种绝对词。看到这类词，先别急着打勾，先在脑子里找反例——找到反例它就是错的。下面 12 条错项全部踩这个套路。
命题对错原因
可重定位目标文件(.o)已含绝对地址，可直接执行错.o 用相对地址，绝对地址是链接时填的
程序头表在 .o / 可执行 / .so 中都存在错.o 没有程序头表，只有节头表
静态链接体积比动态链接大，但外部依赖更低对代码复制进可执行文件
用 -A 追加放行规则能让被禁 IP 恢复访问错必须 -I 插到 DROP 之前
nat 表可作用于 PREROUTING/INPUT/OUTPUT/POSTROUTING对nat 是四链
UID 为 0 的用户只有 root 一个错系统不限制 UID 0 数量，多个是后门信号
SUID 设置后任何用户执行时 EUID 变为文件属主对这正是 SUID 的含义
inode 保存文件名，改文件名会改 inode 号错inode 不含文件名，文件名在目录项
HIDS 装单机看主机行为，NIDS 装网络节点看流量对按部署位置划分
用户态程序知道内核地址就能直接访问错靠页表权限隔离，越权触发异常
fork 在父进程返回子 PID、子进程返回 0对调用一次返回两次
冯·诺依曼结构的核心是程序和数据分开存储错恰恰是混存在同一存储器
