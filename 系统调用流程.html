系统调用流程 · 考试作答详解

对应老师要点一第 6/7/8 条 · 结构按评分点组织 · 可直接默写进卷子

💡 一句话逻辑（答题开头先写这句，直接给分） 系统调用是操作系统提供给用户程序请求内核服务的唯一接口。用户态程序不能直接访问硬件和内核资源，必须通过系统调用"陷入"内核，由内核代为完成，完成后返回用户态。

一、系统调用的三层结构要点一第6条

以调用 time() 为例，一次系统调用要经过三层：

层名称职责
① API 层xyz()（如 time、fork、open）用户程序调用的库函数（glibc 封装）。负责：把系统调用号放进 EAX、参数放进寄存器、执行陷入指令、取回返回值
② 系统调用入口层system_call / entry_INT80_32 / entry_SYSCALL_64进入内核后的统一入口。负责：保存现场、按调用号查系统调用表、分发到对应服务例程、恢复现场返回
③ 服务例程层sys_xyz()（如 sys_time、sys_fork）内核态真正干活的函数，完成实际功能并把结果放入 EAX
⚠ 易错：API 与系统调用不是一一对应。fork 一个 API 对应一个系统调用；strlen 是库函数但根本不涉及系统调用；printf 一个 API 可能内部封装 write 等多个系统调用。答题时点出"API 是外壳、系统调用是内核服务"这层关系更完整。

二、一次系统调用的完整流程（核心，务必分步写全）要点一第7条

以 32 位 x86、用户程序调用 time() 为例，从用户态到内核再回到用户态：

  1. 准备参数：用户程序在用户态调用库函数 time()，库函数把系统调用号放入 EAX（time 为 0xd，即 13），参数按顺序放入 EBX、ECX、EDX、ESI、EDI、EBP。
  2. 触发陷入：执行陷入指令 int $0x80（或 syscall），CPU 发生一次软中断（陷阱 trap，向量号 128）。
  3. 权限级切换：CPU 从用户态（Ring 3）切换到内核态（Ring 0）。
  4. 切换到内核栈：CPU 自动把栈指针从用户栈切换到该进程的内核栈（由 TSS 提供内核栈地址）。这一步最容易被漏！
  5. 保存现场：CPU 自动把用户态的 SS、ESP、EFLAGS、CS、EIP 压入内核栈，保存返回用户态所需的全部信息。
  6. 跳转入口：根据中断描述符表（IDT）查到处理程序地址，跳转到系统调用入口 entry_INT80_32（64 位为 entry_SYSCALL_64）。
  7. 查表分发：入口代码进一步保存通用寄存器现场，然后以 EAX 中的系统调用号为索引，在系统调用表（sys_call_table）中找到对应的服务例程 sys_time 并调用。
  8. 执行内核服务：sys_xyz() 在内核态完成实际工作（如取系统时间），把结果放入 EAX。期间若访问用户空间地址，需用 copy_from_user / copy_to_user 做安全校验。
  9. 恢复现场并返回：恢复保存的通用寄存器和用户态寄存器，执行返回指令 iret（64 位为 sysret），CPU 从内核态（Ring 0）切回用户态（Ring 3）。
  10. 继续执行：返回到用户态下一条指令，EAX 中的返回值被库函数取出，time() 调用结束。

三、态切换时发生了什么（常单独考）

💡 为什么必须换栈？ 用户态和内核态用两个不同的栈。用户栈是"用户的地盘"，可能被恶意构造或破坏，内核不敢信任它，所以一进内核立刻换成内核自己的栈——这样内核干活才安全。这就是"换栈"这一步不能漏的原因。
关键动作说明
① 权限级切换Ring 3（用户态）→ Ring 0（内核态）
② 切换栈用户栈 → 内核栈（两种态各用各的栈）
③ 保存现场把 SS/ESP/EFLAGS/CS/EIP 压入内核栈
④ 跳处理程序查中断向量表，跳到系统调用入口
返回时iret 恢复现场，权限退回 Ring 3

四、参数传递规则（容易单独出填空/选择）

架构系统调用号参数寄存器（按顺序）
32 位 x86EAXEBX、ECX、EDX、ESI、EDI、EBP（最多 6 个；超出则用指针指向内存）
64 位 x86RAXRDI、RSI、RDX、RCX、R8、R9
为什么用寄存器传参、不用压栈？因为用户态和内核态用不同栈，无法用"压栈"方式跨态传参；而且寄存器传参更快。这是答题的加分点。

五、陷入内核的方式演进

方式说明返回
int $0x80传统软中断方式，向量号 128，任何 x86 都支持iret
sysenter / sysexitIntel 专用快速指令（AMD 不支持）sysexit
syscall / sysret现代通用方式，通过 MSR 寄存器直接定位入口，最快sysret

六、系统调用的三大意义（要点一第8条）

① 隔离保护用户态程序不能直接访问底层硬件，通过系统调用把请求交给内核，避免用户程序破坏系统
② 安全所有对硬件的访问都经内核检查把关，防止非法操作
③ 可移植用户程序只面向统一接口编程，底层硬件变化对上层透明，换硬件不用重写程序

七、评分要点 & 常见变体

如果是 6-8 分简答题，这样分配：
· 定义 + 三层结构 —— 2 分
· 完整流程（能写出"传参→int 0x80→切态→换栈→保存现场→查表→sys_xyz→恢复→iret"这条链）—— 3~4 分
· 态切换的换栈/保存现场 —— 1~2 分
· 传参规则（EAX 号 + 参数寄存器）—— 1 分
常见变体 & 陷阱：
① 结合具体系统调用画流程：把 time / fork / rename 套进上面的 9 步即可。rename 号是 0x26，参数 ebx=旧名、ecx=新名。
② fork 与 execve 的特殊性：fork 调用一次返回两次（父进程返回子 PID、子进程返回 0）；execve 覆盖当前进程映像（返回时已是新程序入口，PID 不变）。
③ 不要答错：execve 不是"返回两次"（那是 fork）；态切换必须提"换内核栈"；系统调用是 trap（陷阱），不是普通中断。
背诵口诀：号入 EAX → int 0x80 → 切态换栈 → 存现场 → 查表找 sys_xyz → 干活结果进 EAX → iret 恢复 → 回用户态。
