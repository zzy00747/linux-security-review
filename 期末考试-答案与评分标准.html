一、选择题（5×2′=10 分） —— 共 5 题，10 分

第 1 题（2 分）基础

题干：在 32 位 x86 架构中，下列关于寄存器的叙述正确的是：

正确答案：C．ESP 始终指向栈顶，EBP 通常指向当前函数栈框架的基址

解析：ESP（Extended Stack Pointer）始终指向当前栈顶，随 push/pop 动态变化；EBP（Extended Base Pointer）在函数入口由 movl %esp,%ebp 设定后固定，用于稳定访问参数与局部变量。认为 EIP 执行后不变的学生忽略了 EIP 每执行一条指令即自动递增这一基本事实；认为 EAX 专存栈基址的学生把通用寄存器与 EBP 的职责搞混；认为 CS/DS/ES/SS 可参与算术运算的学生混淆了段寄存器与通用寄存器——段寄存器存放段选择子，不能直接做算术。

易错：ESP 指栈顶（动态）、EBP 指栈基（函数内固定）、EIP 指指令地址（自动递增）。段寄存器不参与算术运算。

第 2 题（2 分）中档

题干：把源文件 hello.c 编译为可执行文件需经四个阶段，下列命令与产物对应关系正确的是：

正确答案：A．gcc -S hello.i -o hello.s，产物是汇编语言源文件

解析：gcc -S 把预处理后的 .i 文件翻译成汇编语言，产物是 .s 汇编源文件。认为 -E 产物可直接运行的学生把预处理（仅做宏展开与文件插入）当成了编译；认为 -c 产物是已完成重定位的可执行文件的学生混淆了可重定位目标文件与可执行文件——重定位发生在链接阶段；认为链接产物是可重定位文件的学生把四个阶段的方向完全颠倒了。

易错：-E→.i（预处理）、-S→.s（编译）、-c→.o（汇编）、链接→可执行文件。四步不可混淆。

第 3 题（2 分）中档

题干：iptables 的 filter 表可作用于 INPUT、FORWARD、OUTPUT 三条链，这三条链的区分依据是：

正确答案：B．按数据包的去向区分：送入本机进程走 INPUT、需转发给其他主机走 FORWARD、本机进程发出走 OUTPUT

解析：三条链的本质区别是数据包的去向：目的地是本机则经 INPUT 链交本机进程；目的地是其他主机且需本机转发则经 FORWARD 链；本机进程自己发出的数据包经 OUTPUT 链。认为按协议区分的学生把链与协议绑定，而 iptables 的链与协议无关，协议匹配靠 -p 参数；认为按源地址区分的学生混淆了链与匹配条件；认为按动作区分的学生更是把规则动作与挂载位置混为一谈。

易错：链看「包去哪」，不看「包是什么协议」或「什么地址」。协议和地址是 -p、-s、-d 匹配条件。

第 4 题（2 分）基础

题干：/etc/passwd 文件中一行内容为 operator:x:11:0:operator:/root:/sbin/nologin，其中 /sbin/nologin 表示：

正确答案：D．该用户被禁止登录系统，通常用于运行服务的系统账号

解析：/etc/passwd 第七个字段是登录 Shell。/sbin/nologin 是一个特殊的「假 Shell」，用户即使通过认证也会立即被退出，从而实现禁止登录。这类账号通常用于运行系统服务（如 bin、daemon、operator），只为满足进程的属主身份需要而存在。认为登录后切目录的学生把 Shell 路径误解为工作目录；认为密码存该文件的学生混淆了 Shell 字段与密码字段（密码在 /etc/shadow）；认为只能 su 切换的学生忽略了 nologin 对 su 同样生效。

易错：/sbin/nologin 和 /bin/false 都是「禁止登录」的标志，不是目录、不是密码文件。

第 5 题（2 分）中档

题干：某文件的权限串为 rwxr-xr--，其对应的八进制数字权限是：

正确答案：A．754

解析：逐段换算：属主 rwx = 4+2+1 = 7；组 r-x = 4+0+1 = 5；其他 r-- = 4+0+0 = 4。故为 754。选 755 的学生把其他用户的 r-- 误算成 r-x（多给了执行位）；选 744 的学生把组的 r-x 误算成 r--（漏掉执行位）；选 764 的学生把组的 r-x 误算成 rw-（把执行位当成了写位）。

易错：r=4、w=2、x=1，逐段相加。r-x 是 5 不是 6（6 是 rw-）。

二、填空题（10 空×1′=10 分） —— 共 10 题，10 分

第 6 题（1 分）基础

题干：在 32 位 x86 中，专门用于指向当前栈顶的寄存器缩写是 ____（全大写）。

参考答案：ESP / esp / %esp

解析：ESP 指向当前栈顶。push 操作先将 ESP 减 4 再写入数据，pop 操作先读出数据再将 ESP 加 4。与之配合的 EBP 指向栈基址，用于在函数内部稳定访问参数与局部变量。

易错：ESP 是栈顶指针（动态），EBP 是栈基指针（函数内固定）。

第 7 题（1 分）中档

题干：要查看 ELF 文件的程序头表（Program Header Table，即段表）信息，应使用 readelf 的 ____ 选项（写选项，如 -h）。

参考答案：-l / -l / —l

解析：readelf -l 显示程序头表（段表），描述各段如何映射到内存。对照记忆：-h 显示 ELF 文件头、-S 显示节头表、-s 显示符号表、-r 显示重定位信息、-a 等价于全选。注意 -l 是小写字母 L。

易错：-l 看段表（程序头）、-S 看节头表、-s 看符号表。大小写敏感。

第 8 题（1 分）中档

题干：C 程序中未初始化的全局变量存放在 ____ 节，该节在可执行文件中不占实际空间（填写节名，带点号）。

参考答案：.bss / bss / .BSS

解析：.bss（Block Started by Symbol）存放未初始化的全局变量与静态变量，属于静态内存分配。因其初值恒为 0，无需在文件中保存实际数据，只记录所需空间大小，section type 为 SHT_NOBITS。

易错：.bss 不占文件空间但占内存空间；.data 才是已初始化变量。

第 9 题（1 分）中档

题干：fork() 系统调用在父进程中返回 ____（填「子进程的PID」或「0」或「-1」）。

参考答案：子进程的PID / 子进程PID / 子进程的pid / 子进程的 PID / >0 / 大于0

解析：fork() 调用一次返回两次：父进程中返回新创建子进程的 PID（大于 0），子进程中返回 0，创建失败返回 -1。这是父子进程区分自身身份的唯一依据。

易错：父得子 PID（>0）、子得 0、错得 -1。判断分支千万别写反。

第 10 题（1 分）基础

题干：iptables 的四张表分别是 filter、nat、mangle 和 ____（填表名）。

参考答案：raw / RAW / Raw

解析：四表：filter（过滤）、nat（地址转换）、mangle（修改数据包内容）、raw（连接跟踪前处理）。五链：PREROUTING、INPUT、FORWARD、OUTPUT、POSTROUTING。

易错：四表是 filter/nat/mangle/raw；五链是 PREROUTING/INPUT/FORWARD/OUTPUT/POSTROUTING。别把表名与链名混。

第 11 题（1 分）中档

题干：禁止源地址为 192.168.100.20 的数据包进入本机，命令为：iptables -A INPUT -s 192.168.100.20 -j ____（填动作名）。

参考答案：DROP / drop / REJECT / reject

解析：iptables -A INPUT -s 192.168.100.20 -j DROP 表示在 INPUT 链末尾追加规则，匹配该源地址的数据包直接丢弃。也可用 REJECT，区别是 REJECT 会向源端返回不可达响应，DROP 静默丢弃。安全场景优先 DROP，避免响应报文暴露主机存活。

易错：DROP 静默丢弃、REJECT 返回响应。安全场景优先 DROP。

第 12 题（1 分）基础

题干：/etc/passwd 文件每一行由 ____ 个字段组成，字段之间用冒号分隔（填阿拉伯数字）。

参考答案：7 / 七

解析：七个字段依次为：用户名、密码占位符、UID、GID、描述信息、主目录、登录 Shell。例如 root:x:0:0:root:/root:/bin/bash。

易错：passwd 是 7 字段，shadow 是 9 字段。

第 13 题（1 分）中档

题干：/etc/shadow 中密码字段以 $6$ 开头，表示使用 ____ 算法加密（填算法名称）。

参考答案：SHA-512 / sha512 / SHA512 / sha-512

解析：$1$ 表示 MD5，$5$ 表示 SHA-256，$6$ 表示 SHA-512。算法标识之后的下一段是盐值（salt，防止彩虹表攻击），再往后是密码的哈希值。SHA-512 输出 512 位摘要，抗暴力破解能力远强于 MD5。

易错：$1$=MD5、$5$=SHA-256、$6$=SHA-512，编号越大越安全。

第 14 题（1 分）中档

题干：Linux 中查看文件 inode 号、权限、属主、大小等元信息，应使用的命令是 ____（填命令名，不含参数）。

参考答案：stat / ls -l / ls -i / ls

解析：stat 命令显示文件的完整元信息，包括 inode 号、权限、硬链接数、UID/GID、大小、三个时间戳（atime/mtime/ctime）等。若只需 inode 号，也可用 ls -i。

易错：stat 看完整元信息，ls -i 只看 inode 号，ls -l 不含 inode。

第 15 题（1 分）中档

题干：使用 nmap 对 192.168.1.0/24 只做主机发现、不做端口扫描，应使用的选项是 ____（写选项，如 -sV）。

参考答案：-sn / -sn / -sP

解析：nmap -sn 192.168.1.0/24 只做主机发现（ping 扫描），通过 ICMP echo、TCP SYN 到 443、TCP ACK 到 80、ARP 等多种手段判断主机是否在线，不扫描端口。旧版本写作 -sP。

易错：-sn 只探活、-sV 探服务版本、-sS 是 SYN 半开扫描。

三、判断题（10×1′=10 分） —— 共 10 题，10 分

第 16 题（1 分）基础

题干：冯·诺依曼体系结构的核心特征是「存储程序」——指令和数据以同等地位存放在存储器中，CPU 按地址顺序取出并解释执行。

正确答案：正确

解析：冯·诺依曼体系结构的两大要点：一是存储器统一存放指令和数据（不区分二者），二是 CPU 作为指令的解释器，按程序计数器指示的地址依次取指、译码、执行。这正是「存储程序计算机」名称的由来。

易错：「存储程序」不等于「程序和数据分开存储」——恰恰相反，二者混存在同一存储器中，这正是冯·诺依曼瓶颈的根源。

第 17 题（1 分）中档

题干：可重定位目标文件（.o）中已经包含了程序运行所需的全部绝对地址，因此可以直接加载执行。

正确答案：错误

解析：可重定位目标文件恰恰不含绝对地址，它使用相对地址和符号引用来表示代码段与数据段之间的关系，正因如此才能在不同内存位置加载——这也是它被称为「可重定位」的原因。绝对地址是在链接阶段由链接器通过重定位填进去的，可执行文件才有完整地址。

易错：「可重定位」的含义就是「地址还没定下来」，说它含绝对地址正好说反。

第 18 题（1 分）中档

题干：程序头表（Program Header Table）在可重定位目标文件、可执行文件和共享目标文件中都存在。

正确答案：错误

解析：程序头表只在可执行文件和共享目标文件中存在，可重定位目标文件中没有。因为程序头表描述的是「段如何映射到内存」，而 .o 文件还没有确定的地址布局，谈不上内存映射。.o 文件只有节头表。

易错：可重定位文件有节头表、没有程序头表。对 .o 执行 readelf -l 会提示 no program headers。

第 19 题（1 分）中档

题干：静态链接生成的可执行文件体积通常比动态链接版本大得多，但对外部库环境的依赖更低。

正确答案：正确

解析：静态链接在编译时把需要的库代码直接复制进可执行文件，因此体积大（PPT 实例：静态版 727908 字节 vs 动态版 7452 字节，相差近 100 倍），但运行时不依赖外部 .so，部署到其他机器更省心。动态链接则相反：体积小、多程序共享同一份库代码，但依赖库的版本存在。

易错：静态=大而自足，动态=小而依赖。两者的体积关系不要记反。

第 20 题（1 分）中档

题干：iptables 的 nat 表可以作用于 PREROUTING、INPUT、OUTPUT、POSTROUTING 四条链。

正确答案：正确

解析：nat 表负责地址转换，可作用于 PREROUTING、INPUT、OUTPUT、POSTROUTING 四条链（PPT 第7讲原文）。注意它与 filter 表（INPUT/FORWARD/OUTPUT 三链）和 raw 表（PREROUTING/OUTPUT 两链）的挂载范围都不同。

易错：nat 是四链、filter 是三链、raw 是两链、mangle 是五链。

第 21 题（1 分）拉分

题干：若 INPUT 链中已存在禁止 192.168.20.0/24 网段的 DROP 规则，此时用 iptables -A INPUT -s 192.168.20.115 -j ACCEPT 追加一条放行规则，则 192.168.20.115 可以正常访问服务器。

正确答案：错误

解析：iptables 规则自上而下逐条匹配，一旦命中即执行动作并停止后续匹配。-A 是在链尾追加，放行规则会排在 DROP 之后，192.168.20.115 的数据包先被 DROP 规则命中而丢弃，永远走不到后面的 ACCEPT。必须用 -I INPUT 把放行规则插入到链首（或 DROP 规则之前）才有效。

易错：规则顺序决定结果。放行规则必须用 -I 插到 DROP 之前，用 -A 追加等于没加。

第 22 题（1 分）中档

题干：/etc/passwd 文件中 UID 为 0 的用户只有一个，即 root，这是系统的硬性约束。

正确答案：错误

解析：系统并不禁止存在多个 UID 为 0 的账号——只要在 /etc/passwd 中新增一行且第三个字段写 0，该账号就拥有超级用户权限。这恰恰是攻击者常用的留后门手法，因此安全审计时要专门检查是否存在非 root 的 UID 0 账号。

易错：UID 0 = 超级用户权限，但系统不限制 UID 0 账号的数量。多出的 UID 0 账号是后门信号。

第 23 题（1 分）拉分

题干：文件的 SUID 位被设置后，任何用户执行该文件时，进程的有效用户 ID（EUID）都会变为该文件属主的 UID。

正确答案：正确

解析：SUID（Set User ID）的作用正是如此：普通用户执行带 SUID 位的文件时，进程的 EUID 临时切换为文件属主的 UID，运行结束后恢复。若文件属主是 root（如 /usr/bin/passwd），则任何用户执行时都以 root 权限运行其中代码——这也是 SUID 程序一旦存在漏洞就能被用于提权的原因。

易错：SUID 改的是 EUID（有效用户 ID），不是 RUID（真实用户 ID）。属主为 root 的 SUID 程序是提权重灾区。

第 24 题（1 分）中档

题干：inode 中保存了文件名，因此重命名文件会导致其 inode 号发生变化。

正确答案：错误

解析：inode 记录文件的权限、属主、时间戳、大小、block 位置等元信息，唯独不记录文件名。文件名保存在目录项中，目录项负责把「名字」映射到「inode 号」。重命名文件只修改目录项，inode 号和文件内容都不变——这也是硬链接能工作的基础。

易错：inode 不含文件名。改名不改 inode；硬链接让多个名字指向同一 inode。

第 25 题（1 分）基础

题干：HIDS 部署在单台主机上，通过监控文件完整性、系统日志和进程行为来发现入侵迹象；NIDS 部署在网络关键节点，通过分析网段流量发现攻击特征。

正确答案：正确

解析：这是按部署位置划分的经典分类：HIDS（Host-based IDS）装在单机上，关注主机内部的文件、日志、进程、系统调用等；NIDS（Network-based IDS）部署在网络关键节点，通过抓包分析流量中的攻击特征。两者互补：HIDS 看不到全网流量，NIDS 看不到主机内部状态。

易错：NIDS 看网络流量、HIDS 看主机行为。别把 N 和 H 的含义搞反。

四、程序分析与综合题（15×3 + 25 = 70 分） —— 共 4 题，70 分

▎程序分析题（3 题 × 15 分 = 45 分）

第 26 题（15 分）

【程序分析题 1】如下所示为 Linux 下运行的某个内嵌汇编代码，请回答后面的问题：

int main() {
    unsigned long val1 = 1;
    unsigned long val2 = 2;
    unsigned long val3 = 0;
    printf("val1:%ld,val2:%ld,val3:%ld\n", val1, val2, val3);
    asm volatile(
        "movq $0,%%rax\n\t"
        "addq %1,%%rax\n\t"
        "addq %2,%%rax\n\t"
        "movq %%rax,%0\n\t"
        : "=m"(val3)
        : "g"(val1), "g"(val2));
    printf("val1:%ld+val2:%ld=val3:%ld\n", val1, val2, val3);
    return 0;
}
（1）请写出蓝色部分（四条汇编指令）每一行代码的作用。（8 分）
（2）请说明约束符 "=m"、"g" 各自的含义。（4 分）
（3）请给出该段程序最后在控制台打印的内容。（3 分）

参考答案见下方解析

解析与评分要点：（1）四条汇编指令的作用（每行 2 分）
· movq $0,%%rax：把立即数 0 送入 64 位寄存器 rax，作用是清零累加器。注意 %% 是内嵌汇编中的转义写法，编译后对应单个 %rax。
· addq %1,%%rax：把第 1 个输入操作数（即 val1）加到 rax 中，累加 val1。%1 指代输出操作数之后的第一个输入操作数。
· addq %2,%%rax：把第 2 个输入操作数（即 val2）继续累加到 rax，累加 val2。
· movq %%rax,%0：把 rax 中的累加结果写回第 0 个操作数，即输出操作数 val3，写回结果。

（2）约束符含义（各 2 分）
· "=m"(val3)：= 表示该操作数是只写的输出（汇编执行后它的值被覆盖）；m 表示该操作数位于内存（memory），编译器直接把 val3 的内存地址交给汇编代码，不经过寄存器中转。
· "g"(val1)：g 表示通用操作数（general），由编译器根据上下文自由选择放在通用寄存器（r）或内存（m）中，是最灵活的约束。

（3）控制台打印内容（3 分）
程序共两次 printf：
第一次（汇编执行前）：val1:1,val2:2,val3:0
第二次（汇编执行后）：val1:1+val2:2=val3:3
因为 val3 = 0 + val1 + val2 = 0 + 1 + 2 = 3，而 val1、val2 未被修改。

评分要点：（1）每行 2 分，必须说明「清零/累加val1/累加val2/写回」四个语义动作，仅逐字翻译指令助记符不给分；（2）每个约束符 2 分，需分别说明 = 的只写语义与 m/g 的存储位置差异；（3）两行打印各 1.5 分，val3 必须为 3。

易错：常见错误：把 %%rax 当成两个寄存器；漏看 movq $0 的清零作用而以为 val3 会在原值上累加；把 %0/%1/%2 的操作数序号数错（%0 是输出，%1 起才是输入）；把 "g" 误认为只表示寄存器（它也可能落到内存）。

第 27 题（15 分）

【程序分析题 2】如下所示为某段 32 位汇编代码，请完成以下任务：

g:
    pushl %ebp
    movl  %esp, %ebp
    movl  8(%ebp), %eax
    addl  $3, %eax
    popl  %ebp
    ret

f:
    pushl %ebp
    movl  %esp, %ebp
    subl  $4, %esp
    movl  8(%ebp), %eax
    movl  %eax, (%esp)
    call  g
    movl  %ebp, %esp
    popl  %ebp
    ret

main:
    pushl %ebp
    movl  %esp, %ebp
    subl  $4, %esp
    movl  $8, (%esp)
    call  f
    addl  $1, %eax
    movl  %ebp, %esp
    popl  %ebp
    ret
（1）请在右侧写出三个函数各自对应的 C 语言代码（变量名自行命名，函数名保持 g、f、main）。（9 分）
（2）说明为什么取参数使用 8(%ebp) 而不是 4(%ebp)。（3 分）
（3）说明 subl $4,%esp 与 movl %eax,(%esp) 这两条指令在传参过程中的配合作用。（3 分）

参考答案见下方解析

解析与评分要点：（1）对应的 C 代码（每函数 3 分）

int g(int x) {
    return x + 3;
}

int f(int x) {
    return g(x);
}

int main(void) {
    return f(8) + 1;
}
逐函数推导：
· g：movl 8(%ebp),%eax 取第一个参数，addl $3,%eax 加 3，ret 返回 eax。故为 return x + 3;。
· f：subl $4,%esp 预留 4 字节局部空间（用于放传给 g 的实参），movl 8(%ebp),%eax 取自己的参数，movl %eax,(%esp) 把它放到栈顶作为 g 的实参，call g 调用，返回值留在 eax 中直接作为 f 的返回值。故为 return g(x);。
· main：movl $8,(%esp) 把 8 放到栈顶作为 f 的实参，call f 后 eax 得 f(8)，addl $1,%eax 再加 1。故为 return f(8) + 1;。

（2）为什么是 8(%ebp)（3 分）
调用者的栈布局（从高地址到低地址）依次是：实参 → 返回地址 → 保存的旧 EBP。执行 call 时 CPU 自动把返回地址压栈，进入被调函数后第一条 pushl %ebp 又把调用者的 EBP 压栈，随后 movl %esp,%ebp 使 EBP 指向这个保存的旧 EBP。
因此：0(%ebp) = 旧 EBP；4(%ebp) = 返回地址；8(%ebp) = 第一个实参。若写成 4(%ebp)，取到的将是返回地址而不是参数，程序必然出错。

（3）两条指令的配合（3 分）
subl $4,%esp 把栈顶下移 4 字节，为即将传入的实参预留空间（相当于「占位」）；movl %eax,(%esp) 把取到的参数值写入这个刚空出的栈顶位置，完成实参入栈。二者合起来等价于一次 pushl %eax，但用两条指令实现可以更清楚地控制栈空间（且在某些编译优化下避免 push 的副作用）。之后 call g 时，g 就能通过 8(%ebp) 正常取到这个实参。

评分要点：（1）每函数 3 分，函数体逻辑必须正确（g 加 3、f 调 g、main 调 f 后加 1），漏掉 addl $1 或写错调用关系不得分；（2）需明确指出 4(%ebp) 是返回地址、8(%ebp) 才是首个参数（3 分）；（3）需说明「预留空间」与「写入实参」的分工（3 分）。

易错：常见错误：把 8(%ebp) 写成 4(%ebp)（忘记返回地址占 4 字节）；漏掉 main 里的 addl $1 写成 return f(8)；把 f 里的 subl $4 误认为是局部变量而多声明一个变量；把 subl+movl 的组合误解为局部变量初始化而非实参传递。

第 28 题（15 分）

【程序分析题 3】如下所示为某段 32 位汇编代码，设执行前 ESP = 0x1000，EBP = 0x2000，栈向低地址方向增长，每次 push/pop 操作 4 字节：

pushl  $8
movl   %esp, %ebp
pushl  %ebp
pushl  $8
addl   $4, %esp
popl   %ebp
（1）请逐条分析每条指令执行后 ESP 的值，并画出执行完毕后的堆栈状态（标明每个单元的地址与内容）。（10 分）
（2）标明当前栈顶和栈基的地址位置，并指出二者是否重合。（3 分）
（3）说明 addl $4,%esp 执行后，原栈顶单元的数据是否被清除。（2 分）

参考答案见下方解析

解析与评分要点：（1）逐条推演与最终堆栈状态（10 分）
· 初始：ESP = 0x1000，EBP = 0x2000。
· pushl $8：ESP 先减 4 得 0x0FFC，再把 8 写入 [0x0FFC]。
· movl %esp,%ebp：EBP = ESP = 0x0FFC（原来的 0x2000 被覆盖）。
· pushl %ebp：ESP 减 4 得 0x0FF8，把 EBP 的值 0x0FFC 写入 [0x0FF8]。
· pushl $8：ESP 减 4 得 0x0FF4，把 8 写入 [0x0FF4]。
· addl $4,%esp：ESP 加 4 得 0x0FF8（栈顶回退一格）。
· popl %ebp：先读出 [0x0FF8] 的值 0x0FFC 送入 EBP，再让 ESP 加 4 得 0x0FFC。

最终堆栈状态（地址小的在下方，栈向下增长）：

地址        内容          说明
0x0FF4      8             已被 addl $4 移出栈顶范围，数据仍残留
0x0FF8      0x0FFC        已被 popl 弹出，数据仍残留
0x0FFC      8             ← 当前栈顶（ESP 指向）
有效栈范围是 [0x0FFC, 0x1000)。

（2）栈顶与栈基位置（3 分）
· 栈顶 ESP = 0x0FFC，指向内容 8。
· 栈基 EBP = 0x0FFC（最后一条 popl %ebp 把 [0x0FF8] 中的 0x0FFC 恢复进 EBP）。
二者恰好重合于 0x0FFC。

（3）数据是否被清除（2 分）
没有被清除。addl $4,%esp 只修改 ESP 寄存器，使栈顶指针上移 4 字节，并不对内存做任何写操作。[0x0FF4] 中原来的 8 依然存在，只是已不在有效栈范围内——后续若再有 push 操作，该单元才会被新数据覆盖。这也是栈上残留敏感数据（如密码、密钥）可被取证读取的原因。

评分要点：（1）每条指令后的 ESP 值各 1.5 分（共 9 分），最终堆栈图 3 个单元的地址与内容各约 0.33 分（共 1 分）；（2）ESP 值 1.5 分、EBP 值 1.5 分，须明确指出重合；（3）必须答「未清除」并解释原因（2 分）。

易错：三个高频错误：① push 是「先减后写」、pop 是「先读后加」，顺序写反地址全错；② 忘记 movl %esp,%ebp 会覆盖 EBP 的原值 0x2000，仍按 0x2000 作答；③ 误认为 addl $4,%esp 会清零内存，答成「数据被清除」。

▎综合题（1 题 × 25 分 = 25 分）

第 29 题（25 分）

【综合题】小明大学毕业后进入某互联网公司担任网络管理员，负责维护管理公司基于 Linux 的 Web 服务器。为提高服务器安全防护水平，小明在服务器上配置了 iptables 防火墙。请根据该场景回答下列问题：

（1）小明在终端输入了什么命令，可以显示 INPUT 链下所有规则（含 policy 与规则序号）？（3 分）

（2）小明发现 IP 地址 192.168.100.20 向服务器进行了多次端口扫描，想禁止该 IP 对服务器的全部访问，应如何操作？并说明为什么选用 DROP 而非 REJECT。（5 分）

（3）经过一段时间，发现网段 192.168.20.0/24 内大量 IP 频繁对服务器执行 ping 操作，需要禁止该网段的 ping 请求，但不能影响该网段其他正常业务，该如何处理？（5 分）

（4）公司技术人员恰好在该网段 192.168.20.0/24 内远程调试 Web 应用，需要允许其终端（IP 为 192.168.20.115）访问服务器。请写出命令，并说明为什么不能用 -A。（6 分）

（5）领导怀疑有网络测绘公司频繁对服务器的 UDP 端口扫描，导致 Web 服务出口带宽被挤占，需要对 UDP 流量限速。请写出完整的规则组合。（6 分）

参考答案见下方解析

解析与评分要点：（1）显示 INPUT 链规则（3 分）
iptables -L INPUT -n --line-numbers
或 iptables -t filter -L INPUT -n --line-numbers。
说明：-L 列出规则；-n 以数字形式显示地址与端口（不做反向 DNS 解析，速度快）；--line-numbers 显示规则序号，便于后续用 -D INPUT 序号 精确删除。默认表即 filter，-t filter 可省略。

（2）禁止单个 IP 全部访问（5 分）
iptables -A INPUT -s 192.168.100.20 -j DROP
为什么用 DROP 而非 REJECT：DROP 静默丢弃数据包，不向源端返回任何响应，攻击者的扫描器只能等到超时，无法判断目标主机是否存在；REJECT 会向源端返回 ICMP 不可达（或 TCP RST），相当于主动告知「这台主机在线且拒绝了你」，反而帮助扫描者确认目标存活、加快后续探测。因此安全防护场景应优先使用 DROP。

（3）只禁止该网段 ping（5 分）
iptables -A INPUT -s 192.168.20.0/24 -p icmp -j DROP
关键点：必须加 -p icmp 限定协议。若只写 -s 192.168.20.0/24 -j DROP，会连同该网段的 HTTP、SSH、数据库等所有流量一并封掉，造成大面积业务中断。ping 使用 ICMP echo request（类型 8），因此限定 icmp 协议即可精准封禁 ping 而保留其他业务。

（4）放行网段内单个 IP（6 分）
iptables -I INPUT -s 192.168.20.115 -j ACCEPT
为什么不能用 -A：iptables 规则自上而下逐条匹配，一旦命中即执行动作并停止后续匹配。-A 是把规则追加到链末尾，而第（3）问已经用 -A 在链尾（更早的位置）放了一条禁止 192.168.20.0/24 的 DROP 规则。若用 -A 追加放行规则，它会排在 DROP 之后，192.168.20.115 的数据包会先被 DROP 命中丢弃，根本走不到后面的 ACCEPT——这条放行规则形同虚设。必须用 -I 把 ACCEPT 插入到链首部（或至少插到 DROP 之前，如 -I INPUT 1），才能让它先于 DROP 生效。

（5）UDP 限速（6 分）
iptables -A INPUT -p udp -m limit --limit 10/s --limit-burst 20 -j ACCEPT
iptables -A INPUT -p udp -j DROP
说明：第一条用 limit 模块做令牌桶限速——允许 UDP 流量以每秒 10 个包的速率通过，突发上限 20 个包；第二条作为兜底，把超出限速被 limit 模块「漏过」的 UDP 包全部丢弃。两条必须配合使用：只有 limit 而没有兜底 DROP，超出的包会继续往下走并被默认策略处理；只有 DROP 而没有 limit，则会封死所有 UDP，连正常的 DNS 查询都受影响。
若需针对特定端口（如只限制扫描常用的高位端口），可加 --dport 范围限定。

评分要点：（1）命令含 -L 与 -n 即给 2 分，含 --line-numbers 再给 1 分；（2）命令 2 分，DROP 与 REJECT 的差异说明 3 分（须点出「不返回响应、不暴露主机存活」）；（3）命令 3 分（缺 -p icmp 只给 1 分），说明「不能影响其他业务」的理由 2 分；（4）命令 3 分（写成 -A 不给分），-I 与 -A 的顺序差异说明 3 分；（5）两条规则各 2 分，说明必须配合使用 2 分。

易错：本题四个陷阱：① 第（3）问漏写 -p icmp 会误封整个网段所有业务；② 第（4）问用 -A 追加放行规则，因排在 DROP 之后而永远不生效——这是全题最核心的考点；③ 第（2）问误以为 REJECT 更「明确」而选它，实际上会暴露主机存活；④ 第（5）问只写 limit 不写兜底 DROP，限速形同虚设。
