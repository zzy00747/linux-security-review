程序分析题 · 专项练习（5 道）

对齐老师黑板「程序分析 15′×3」题型 · 每题先自己做，点开看答案 · 数字与指令均为新编

💡 做题前先记住三套口诀 堆栈画图：push 先减后写、pop 先读后加；addl $N,%esp 只抬栈顶不清数据。
汇编转 C：参数看 8(%ebp)、运算看 add 立即数、调用看 call 前后。
内嵌汇编：每行说"语义"不是翻译助记符；%0是输出、%1起是输入。

第 1 题 · 内嵌汇编分析 15 分

如下所示为 Linux 下运行的某个内嵌汇编代码，请回答后面的问题：

int main() {
    unsigned long val1 = 5;
    unsigned long val2 = 3;
    unsigned long val3 = 0;
    printf("val1:%ld,val2:%ld,val3:%ld\n", val1, val2, val3);
    asm volatile(
        "movq $0,%%rax\n\t"
        "addq %1,%%rax\n\t"
        "subq %2,%%rax\n\t"
        "movq %%rax,%0\n\t"
        : "=m"(val3)
        : "g"(val1), "g"(val2));
    printf("val1:%ld-val2:%ld=val3:%ld\n", val1, val2, val3);
    return 0;
}

（1）请写出蓝色部分（四条汇编指令）每一行代码的作用。（8 分）
（2）说明约束符 "=m" 的含义。（3 分）
（3）请给出该段程序最后在控制台打印的全部内容。（4 分）

点击查看参考答案

（1）四条指令的作用（每行 2 分）

  1. movq $0,%%rax：把立即数 0 送入 64 位寄存器 rax，清零累加器（%% 是内嵌汇编转义，编译后即 %rax）。
  2. addq %1,%%rax：把第 1 个输入操作数（val1）加到 rax，累加 val1。
  3. subq %2,%%rax：把第 2 个输入操作数（val2）从 rax 减掉，减去 val2。
  4. movq %%rax,%0：把 rax 的结果写回第 0 个操作数（输出 val3），写回结果。

（2）"=m" 的含义（3 分）：= 表示该操作数是只写的输出（汇编执行后它的值被覆盖）；m 表示该操作数位于内存，编译器直接把 val3 的内存地址交给汇编代码，不经寄存器中转。

（3）控制台打印内容（4 分，每行 2 分）

val1:5,val2:3,val3:0
val1:5-val2:3=val3:2

因为 val3 = 0 + 5 − 3 = 2（先加 val1 再减 val2），val1、val2 未被修改。

⚠ 易错：把 subq 记成加法（那就是 8 不是 2）；把 %%rax 当成两个寄存器；漏看 movq $0 的清零作用。

第 2 题 · 汇编转 C 15 分

如下所示为某段 32 位汇编代码，请回答问题：

h:
    pushl %ebp
    movl  %esp, %ebp
    movl  8(%ebp), %eax
    subl  12(%ebp), %eax
    popl  %ebp
    ret

main:
    pushl %ebp
    movl  %esp, %ebp
    subl  $8, %esp
    movl  $10, (%esp)
    movl  $4, 4(%esp)
    call  h
    addl  $2, %eax
    movl  %ebp, %esp
    popl  %ebp
    ret

（1）请写出 h 和 main 各自对应的 C 语言代码（函数名保持 h、main，变量名自拟）。（9 分）
（2）说明 h 中取第 2 个参数为什么用 12(%ebp)。（3 分）
（3）该程序 main 最终的返回值是多少？（3 分）

点击查看参考答案

（1）对应的 C 代码（每函数 4.5 分）

int h(int x, int y) {
    return x - y;
}

int main(void) {
    return h(10, 4) + 2;
}

推导：h 中 movl 8(%ebp),%eax 取第 1 个参数 x，subl 12(%ebp),%eax 减去第 2 个参数 y，ret 返回 eax → x - y。main 中先给栈顶放 10、下一个放 4（即传入 h(10,4)），call h 后 addl $2,%eax 再加 2。

（2）为什么是 12(%ebp)（3 分）：栈布局从 EBP 往高地址依次是 0(%ebp)=旧EBP、4(%ebp)=返回地址、8(%ebp)=第1个参数、12(%ebp)=第2个参数。每个参数占 4 字节，所以第 2 个参数在 12(%ebp)。

（3）返回值（3 分）：h(10,4) = 10 − 4 = 6，再 +2 = 8。

⚠ 易错：把第 2 个参数写成 8(%ebp)（那是第 1 个）；把 subl 12(%ebp) 的方向搞反（应该是 eax − 参数，即 x − y）；漏掉 main 里的 addl $2。

第 3 题 · 堆栈画图 15 分

如下所示为某段 32 位汇编代码，设执行前 ESP = 0x2000，EBP = 0x3000，栈向低地址增长，每次 push/pop 操作 4 字节：

pushl  $16
movl   %esp, %ebp
pushl  %ebp
pushl  $16
addl   $8, %esp
popl   %ebp

（1）请逐条写出每条指令执行后 ESP 的值。（8 分）
（2）画出执行完毕后的堆栈状态（标明每个单元的地址与内容）。（4 分）
（3）写出最终 ESP 和 EBP 的值，并说明 EBP 里装的是什么。（3 分）

点击查看参考答案

（1）逐条 ESP（每条约 1.3 分）

指令ESP内存动作
初始0x2000—
pushl $160x1FFC[0x1FFC] = 16
movl %esp,%ebp0x1FFCEBP = 0x1FFC（覆盖原 0x3000）
pushl %ebp0x1FF8[0x1FF8] = 0x1FFC
pushl $160x1FF4[0x1FF4] = 16
addl $8,%esp0x1FFC只抬栈顶，数据残留
popl %ebp0x2000EBP = [0x1FFC] = 16

（2）最终堆栈状态（4 分）

地址        内容          说明
0x1FF4      16            已被 addl $8 移出栈顶，数据残留
0x1FF8      0x1FFC        已被 addl $8 越过，数据残留
0x1FFC      16            ← popl 从这里读出 16 给 EBP

（3）最终值（3 分）：ESP = 0x2000，EBP = 16。EBP 里装的是 16（不是 0x1FFC！）——因为 addl $8,%esp 把栈顶从 0x1FF4 跳过 0x1FF8 拉回到 0x1FFC，popl %ebp 读的是当前 ESP 指向的 [0x1FFC] 处的值，即最初 pushl $16 压进去的 16。

⚠ 这是本题最大的坑：如果以为 popl 读 [0x1FF8]，就会答 EBP=0x1FFC（错）。popl 读的是"当前 ESP 指向的单元"，addl $8 已经让 ESP 越过了 0x1FF8。

第 4 题 · fork 进程分析 15 分

阅读下面的 C 代码并回答问题：

int main() {
    pid_t pid;
    printf("A\n");
    pid = fork();
    if (pid == 0) {
        printf("B\n");
    } else {
        pid = fork();
        if (pid == 0)
            printf("C\n");
        else
            printf("D\n");
    }
    printf("E\n");
    return 0;
}

（1）写出把该代码编译为可执行程序的命令。（2 分）
（2）程序运行后，A、B、C、D、E 各打印几次？（7 分）
（3）画出父子进程关系图，并标明各进程打印的内容。（6 分）

点击查看参考答案

（1）编译命令（2 分）：gcc -o fork_demo fork_demo.c（三要素：gcc、源文件、-o 输出）。

（2）各打印次数（7 分）

字符次数哪些进程打印
A1 次只有最初的 P0（在第一次 fork 之前）
B1 次P1（第一次 fork 的子进程，pid==0）
C1 次P2（P0 第二次 fork 的子进程）
D1 次P0（第二次 fork 的父进程）
E3 次P0、P1、P2 三个进程最后都会走到 printf("E")

（3）父子进程关系图（6 分）

        P0（打印 A）
        ├── fork#1 ──→ P1（子,pid=0）  打印 B，再打印 E
        └── fork#2 ──→ P0（父,pid>0）  打印 D，再打印 E
                        └──→ P2（子,pid=0） 打印 C，再打印 E

共产生 3 个进程：P0、P1、P2。P1 走 if 分支打印 B；P0 走 else 再 fork 一次，P0 打印 D、新子进程 P2 打印 C；三者最后都执行到最后一句 printf("E")。

⚠ 易错：① 以为 fork 后只有子进程继续（漏掉父进程也走 else）；② 数不清进程个数（两次 fork → 3 个进程）；③ 漏算 E（三个进程都会打印 E）；④ 混淆 if(pid==0) 是子进程分支。

第 5 题 · 内嵌汇编触发系统调用 15 分

如下代码用内嵌汇编直接触发 time 系统调用，请回答问题：

int main(void) {
    time_t tt;
    asm volatile(
        "mov $0, %%eax\n\t"
        "mov $0xd, %%eax\n\t"
        "int $0x80\n\t"
        "mov %%eax, %0\n\t"
        : "=m"(tt));
    printf("time=%ld\n", tt);
    return 0;
}

（1）逐行说明四条汇编指令的作用。（8 分）
（2）这段代码调用的是哪个系统调用？系统调用号是多少？为什么？（4 分）
（3）如果要改成触发 rename 系统调用（把 hello.c 改名为 newhello.c），系统调用号和参数应如何设置？（3 分）

点击查看参考答案

（1）四条指令作用（每行 2 分）

  1. mov $0, %%eax：先把 eax 清零（清空残留值，保证干净）。
  2. mov $0xd, %%eax：把系统调用号 0xd（十进制 13） 放入 eax——即告诉内核"我要调 time"。
  3. int $0x80：执行陷入指令，从用户态切换到内核态，内核按 eax 中的调用号执行 time 服务。
  4. mov %%eax, %0：内核把返回值（当前时间）放在 eax 中，这条把 eax 写回输出操作数 tt。

（2）调用的系统调用（4 分）：调用的是 time 系统调用，系统调用号 0xd（13）。判断依据是 mov $0xd,%eax 把 13 放进了 eax（系统调用号寄存器）。32 位 x86 Linux 中 time 的调用号就是 13（64 位是 201/0xc9）。

（3）改成 rename（3 分）：rename 的系统调用号是 0x26（38）；需要传两个参数——旧文件名放 ebx、新文件名放 ecx： 

movl $0x26, %%eax   /* rename 系统调用号 */
movl oldname, %%ebx  /* 旧文件名指针 hello.c */
movl newname, %%ecx  /* 新文件名指针 newhello.c */
int  $0x80
返回值 0 表示成功。

⚠ 易错：把系统调用号放错寄存器（必须是 eax，32 位）；忘记参数要放 ebx/ecx（不是压栈）；记错 rename 号（0x26）。
练习建议：先不看答案独立做完 5 道，再对照解析。第 3 题（堆栈）和第 4 题（fork）是最容易丢分的，重点核对 popl 到底读了哪个单元、fork 后到底几个进程。做完这套，老师那三类程序分析题基本就稳了。
